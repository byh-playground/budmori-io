# budmori

## 브라우저 원본 모듈 실행 (2026-10-24)

- `index.html` → `src/bootstrap.js` → `src/farm-app.js` 순서로 실행합니다.
- 게임은 원본 ES 모듈을 직접 가져옵니다.
- 원본 SVG와 고정된 GameKit SDK 해시 검증, 저장·네트워크 계약은 유지합니다.
- `npm run check`는 문법·코드·모듈 계약을 검사하며 실행 파일을 만들지 않습니다.
- GitHub Pages는 기존 `main /`의 원본 HTML·JS·CSS·SVG를 게시합니다.

농장의 일꾼과 번식·합체로 병력을 키워, 거대 보스에 도전하는 2.5D WebGL 게임입니다. 싱글 플레이 전용입니다. 메인 버전은 `src/version.js`에서 관리합니다.

[공개 게임](https://byh-playground.github.io/budmori-io/)

농장과 전장 모두 화면을 드래그해 이동하고, PC 휠이나 모바일 두 손가락으로 확대·축소합니다. 두 손가락의 중심을 옮기면 함께 패닝됩니다. 전장은 69×51, 야외 농장은 기존 46×34입니다. 기본 전투 시점은 기존 병력 크기를 유지하고, 직접 카메라를 움직인 뒤에는 새 층에 들어갈 때까지 자동 프레이밍하지 않습니다.

## 유물

탑의 유물 문에서 9종 자동 스킬(낙뢰·운석·유성우·거대화·복사·치유의 비·거대 망치·우주선·뇌운) 중 하나를 얻거나, 이미 가진
유물을 1레벨 올립니다. 한 판에 최대 3종, 유물당 최대 Lv.5이며 그 판이 끝나면 모두 사라집니다. 조건과 5초 재사용 시간이
모두 준비되면 자동 발동합니다. [수치·강화축·복사/버프 정책](docs/formation-skills.md)에 초기값과 경계를 정리했습니다.

탑의 강화 카드를 선택하면 보스도 같은 스탯·패시브·스킬 후보 세 장 중 하나를 자동 선택합니다. 복사·불사만 제외하며, 기술은 최대 3종·각 5레벨로 성장하고 새 등반에는 초기화됩니다. 같은 카드 화면에서 내 획득·보스 후보·선택·실제 강화 변화를 이어 보여주고, 다음 문에도 마지막 결과가 남습니다. 다음 전투의 공통 기술 HUD에는 새로 얻거나 강화한 보스 기술을 표시하며 충전·5초 쿨·시전 상태는 실제 값을 사용합니다. 스킬 모델·그림은 공유하되 보스 공격의 범위와 시각 크기는 보스 몸집을 기준으로, 병력의 기존 스킬은 대상 크기를 기준으로 합니다. 기존 물리 공격은 시전 중 멈추며 농장 보스의 카드 정책은 바뀌지 않습니다.

보리까지 9종의 성장 트리를 사용할 수 있으며 기본 위력·실제 등급에 따라 도리깨 방어 파쇄도 강해집니다.

병종 기본 스탯은 [역할 표](docs/unit-stats.md#병종별-기본-역할)를 사용합니다. 옥수수·밤톨은 거리를 유지하는 대신 체력이 낮고, 근접 병종은 접근 위험에 맞춰 체력·방어·접촉 위력이 높습니다. 밤톨의 선호 사거리는 3.6, 부채꼴 이상 형태는 4.2이며 기존 사거리 연구 배율을 더합니다. 큰 보스의 평타는 공격 범위와 몸체 이동을 따로 설정해, 무기 동작에 맞추려고 몸 전체가 멀리 미끄러지거나 기본 도약 높이가 몸집만큼 증폭되지 않습니다.

## 실행과 검증

실행은 저장소 루트를 제공하는 정적 서버와 WebGL 브라우저만 필요합니다. 아래 Node.js 도구는 선택적인 검증용이며 제품 파일을 생성하지 않습니다.

```sh
npm ci
npm run check
node scripts/gamekit-provenance.cjs
npm test
npm run test:breed-allocation
npm run test:codex
npm run test:corn-growth
```

정적 서버로 저장소 루트를 열면 `index.html` → `src/bootstrap.js` → `src/farm-app.js`와 그 원본 ES 모듈을 직접 실행합니다. 별도 번들·concat·생성 산출물 배포 단계는 없습니다. GameKit은 `gamekit-lock.json`의 불변 CDN ESM을 검증 후 로드합니다.

`node scripts/gamekit-provenance.cjs`는 고정 SDK의 Git 객체·manifest·SHA-256과 원본 import graph·SVG를 읽기 전용으로 검증합니다. `npm test`의 종료·복귀 흐름은 저장 뒤 렌더 프레임 취소, 자원 해제, 뒤로 가기 캐시의 `pageshow` 재로딩과 이어하기를 함께 확인합니다.

`assets/troops/`의 SVG가 각 캐릭터 몸체 벡터 아트, 클립, 소켓의 단일 원본입니다. 표정은 SVG에 그려 두지 않고 [얼굴 레이어](./docs/unit-face-layer.md)가 몸 위에 코드로 그립니다. 고정 GameKit SVG 로더가 원본을 읽어 실행 메모리에서 메시를 만들며, 저장소 파일을 재작성하거나 배포용 메시를 생성하지 않습니다. `npm run check`는 원본 import graph와 자산 무결성을 읽기 전용으로 확인합니다. GameKit의 native `play`, `setExpression`(몸 변형만), `seek`, `getSocket`, `draw` API를 사용하고 모든 캐릭터를 공통 `PresentationRuntime` 표시 시각에 맞춥니다. 얼굴은 몸의 세 anchor socket에서만 만들며 SVG 옆 모션 sidecar는 사용하지 않습니다.

병력의 충돌 반경·높이와 표시 배율은 원본의 이름 있는 몸통 외곽선·지면 소켓을 공유합니다. 옥수수 낟알은 발사 순간 몸통 높이의 20%이며, 최소 표시 픽셀은 충돌 크기에 영향을 주지 않습니다. 측정 기준과 저장 호환성은 [몸 크기와 투사체 크기](docs/unit-body-dimensions.md)에 정리했습니다.

기본 PR CI는 검증 도구 준비 후 `npm run check`와 실제 9종 혼합 전투 source smoke만 실행합니다. 같은 흐름 안에서 9종 보스의 자연 기본 공격·고유 효과와 공통 FarmSession/native 렌더도 확인합니다. 보스는 동일 병종 SVG 원본을 standard 품질로 사용하고, 병종 기본 공격·특수 패턴·카드 시전은 한 번에 하나만 준비합니다. 병종별 사용자 흐름과 카메라·산개·탑 검사는 필요할 때 workflow_dispatch로만 실행하며, 자동으로 매 변경마다 전체 행렬을 실행하지 않습니다. 병종 선택의 `all`은 기존 옥수수·완두콩·팥·밤톨·땅콩 5종이며, 기능 통합은 `functional`, 성능은 기본 꺼짐인 `performance` 입력으로 별도 선택합니다. skipped 작업은 통과로 세지 않습니다. 브라우저 스모크 테스트(`tests/smoke.e2e.mjs`)는 필요할 때 `npm test`로 실행하며, 게임 라이브러리를 `vendor/upstream`에서 받아 오프라인으로 돌고 약 70초 걸립니다. 필요한 변경에서는 번식 몫 UI 시나리오와 기존 전체 스모크도 검사하며, `npm run test:breed-allocation`으로 따로 실행할 수 있습니다. 옥수수 성장 흐름은 `npm run test:corn-growth`로 구매·초기화·실제 형태 미리보기·저장 복원·런 잠금을 검증하고 `tests/output/corn-growth/`에 프레임과 보고서를 남깁니다. 각 브라우저 검증 명령은180초 이내로 실행합니다. 콩의 동일 사용자 흐름은 `npm run test:pea-growth:case -- ui desktop` (또는 `previews`/`battle`, `mobile`/`landscape`)로 실행하며 `tests/output/pea-growth/`에 기록합니다. 팥은 `npm run test:redbean-growth:case -- ui desktop`으로 실행하며 `previews-low`/`previews-high`/`battle`/`battle-extra`/`continuity`/`migration` 사용자 흐름을 각각180초 이내로 검사합니다. 병종별 브라우저 작업은 병종·뷰포트별로 분리되어 기존 검증을 생략하지 않습니다. 밤톨은 `node tests/chestnut-growth.e2e.mjs desktop` (또는 `landscape`)으로 투자·농장 저장·런 흐름을, `node tests/chestnut-motion.e2e.mjs desktop`으로 여섯 가시 평타·보스 경계·실제 발사·취소·연속성을 검증합니다. 땅콩은 `npm run test:peanut-growth:case -- ui desktop` 및 같은7개 사용자 흐름으로 한 본체의 실제 두 알 동작·사망 분열·저장 복원을 검사합니다. 별도 `PEANUT_PERFORMANCE_BASE_ROOT=/path/to/0.34.0 npm run test:peanut-performance`는 정확한0.34.0 기준본과 최대200 영구 유닛·실제 분열체2마리 장면을 세 번 교대 비교합니다. 모바일은 Chromium 터치 에뮬레이션이며 실제 기기 검증과 구분합니다.

## 농장

보상으로 받은 성장 중 새싹은 `assets/troops/sprout.svg`의 원래 모습으로 돌아다니며 농장 먹이를 5초에 한 번, 세 번 자동으로 먹으면 정해진 병종으로 자랍니다. 성장 중에는 노동·오프라인 생산·번식에 참여하지 않고, 성체가 된 뒤 역할 비율에 따라 배정됩니다. 새싹 병종 자체와 먹이가 필요한 성장 단계는 구분합니다.

농장은 200마리 정원으로 시작하며 병종 성장과 별개인 전체 XP·레벨로 최대 1,000마리까지 확장됩니다. 기존 보유 병력과 병종 투자는 보존합니다. 먹이·번식·합성·성장·휴식은 농장에서만 진행하며 전투 중에는 멈춥니다. 일꾼의 곡식 생산, 부모의 준비 먹이, 10초 번식 휴식과 5초 자식 성장은 기존 규칙을 유지합니다.

농장 관리의 번식 몫은 병종 아이콘을 선택한 뒤 가로 슬라이더나 ± 버튼으로 1%씩 조절합니다. 나머지 병종은 기존 비율대로 배분하고 표시 합계는 100%를 유지합니다. `균등`을 누르면 보유 병종 사이에 같은 몫을 나누며 정수 나머지는 병종 순서대로 배분합니다. 메뉴 진입·병종 선택·재접속만으로 기존 저장 비율을 바꾸지 않습니다. 전체 번식 인원은 농장 화면의 역할 나누기로 정하며, 배분 계획은 성장·휴식 등을 반영한 현재 활동 인원과 다를 수 있습니다.

## 자동 군단전

병종은 완두콩·옥수수·팥·밤톨·땅콩·호두입니다. 땅콩은 한 개체·한 체력으로 남아 두 알이 T1 교대 두 타부터 T6 전개·스윕·중앙 찍기 다섯 타까지 협공하며, 연구 형태는 실제 합성 등급을 넘지 않습니다. 각 공격의 슬롯 비중 합계는100%이고 사망 시 별도의 T1 분열체 두 마리가 생깁니다. 분열체는 부모 성장을 다시 적용하거나 재분열·영구 보유·번식·합성하지 않습니다. 호두는 망치로 한 번 내려찍습니다. 두 공격의 피해는 기존 등급 스탯에서 파생해 공통 전투 대상 처리기로 전달됩니다.

농장의 탑 오르기에서 시작층을 선택해 100층에 도전합니다. 최고 시작층은 최고층의 20% 아래이며 더 낮은 층도 선택할 수 있습니다. 병력은 탑 입구로 행진한 뒤 농장 최대 정원의 절반만 전선에 배치되고 나머지는 예비대가 됩니다. 등급별 슬롯 차이는 없으며 전선 상한은 최대 500마리입니다. 병종 우선순위에 따라 약 1.5초 동안 처음 배치하고 전사자 자리는 자동 보충합니다.

교전·산개·후퇴 중 하나를 선택해 전체 병력과 예비대의 지속 명령을 바꿉니다. 산개는 간격을 넓히며 공격하고, 후퇴는 미발동 기본 공격 준비를 취소해 적에게서 멀어집니다. 발사된 탄이나 시작한 도약은 취소하지 않습니다. 명령 자체의 스탯 보너스는 없습니다.

층마다 유한한 보스 명단이 시간에 따라 합류합니다. 현재 적을 일찍 전멸시키면 다음 적이 즉시 등장하며 모두 처치해야 한 번의 층 보상을 받습니다. 기존 강화층·문 선택·보스 카드 경로와 다음 전투 생존자 회복·전사자 등급별 휴식은 유지합니다. 100층의 여러 수호자 이후 최종 보스를 쓰러뜨리면 건너뛸 수 있는 정상 장면을 보여줍니다. 보상은 장면 전에 확정하며 새로고침은 농장으로 복귀합니다.

입구·정원·무기고·왕실 홀·테라스의 다섯 배경은 시각 테마이며 환경 위험이나 경로 장애물은 없습니다. 목표는 선택 시작층부터 도전 종료까지 5–15분이지 전체 100층의 강제 압축이나 시간 만료 종료가 아닙니다. 자세한 [규칙·초기 조정값·저장 계약](docs/tower-army.md)을 참고하세요.

적의 위험 예고는 실제 수평 피해 범위의 합집합을 붉은 반투명 면과 하나의 바깥 외곽선으로 표시합니다. 공격 준비가 끝날수록 색이 진해지고 타격 직후 짧게 밝아지며, 내부 도형의 겹친 선은 그리지 않습니다. 공중 높이와 실제 접촉 판정은 기존 규칙을 따릅니다.

전투에서 쓰러진 병력은 사라지지 않고 회복하는 동안 잠자며, 전투가 끝나면 농장으로 돌아옵니다. 강화는 짧게 지속되며 재사용 대기시간이 있습니다.

- 병력은 전방위에 배치되고, 움직이는 보스 주변의 각도별 위치를 따라 접근·공격합니다. 돌격은 실제 몸체 접촉, 곡사 씨앗탄은 보스 몸체 또는 지면과의 실제 스윕 접촉, 도약은 몸체 접촉 또는 착지로 판정합니다. 준비·발사/이동·접촉·반동·회복을 구분합니다.
- 보스는 살아 있는 병력을 선택해 추격하며, 전체 원 휩쓸기·전방 내려찍기·돌진·도약 내려찍기·부채꼴 휩쓸기·입 소환 6패턴을 공통 가중치·쿨타임으로 선택합니다. 준비 중 방향을 추적하다 마지막 0.25초에 고정하고, 실제 접촉과 높이 조건에 따라 피해·에어본을 판정합니다. 입 소환은 한 번에 최대 4마리, 살아 있는 소환 병력 10마리 상한을 유지합니다. 실행 중 패턴 한 곳이 단계·경과 시간·표적·명중 집합을 소유하며, 같은 패턴의 중복 명중을 막습니다. 회복 뒤 다음 추격으로 돌아가고 전투 종료 시 남은 행동을 취소합니다.
- 농장과 전장 경계는 모두 반경 23×17의 타원 월드 영역입니다. 보스 반경 4.4와 높이 5.2를 실제 접촉에 사용하고, 병력과 보스는 바깥으로 나가지 않습니다. 별도 지형 벽 높이 시스템은 없습니다.
- 핀치나 마우스 휠로 확대·축소합니다. 한 손가락 또는 마우스 왼쪽 드래그로 넓은 맵을 둘러보며, 맵과 화면 크기에 맞춰 이동 범위를 제한합니다. 손을 떼거나 메뉴·입력 취소·창 이탈은 진행 중 입력을 정리하며 장면 전환 때 시야는 중심으로 돌아갑니다. 무기·예고·그림자와 지면 터치 좌표는 같은 카메라 투영을 사용합니다. 시야 위치는 표시 전용 임시 상태이며 몸체·먹이의 시뮬레이션 좌표를 바꾸지 않습니다. 탑 안에서는 전장이 한 화면에 맞춰져 이동·확대가 없습니다. 합성 버튼을 꾹 누르면 0.1초마다 합성합니다.
- 병력은 체력이 0이면 해당 전투에서 쓰러집니다. 전선과 예비대가 모두 소진되면 패배, 해당 층의 보스 명단을 전부 처치하면 승리합니다. 투사체와 공격 행동을 정리하고 공중에 있던 몸은 중력으로 착지합니다. 정원 복귀 시 병력은 원래 자리·체력으로 회복합니다.

`CombatFeel`은 확정된 공통 전투 사건의 실제 접점·법선·대상을 읽어 국소 섬광, 방향 불꽃, 착지 먼지와 제한된 오디오를 만듭니다. 강한 피격의 대상 표시만 최대 35ms 멈추며 시뮬레이션·입력은 계속 진행합니다. 효과 48개·공유 오디오 4 voice 상한을 두고, 동작 줄이기 설정은 이 표현 정지와 변형을 생략합니다. 전체 화면 점멸·전역 hitstop·상시 카메라 흔들림은 사용하지 않습니다.

착지(`unit-land`) 표시 복사본만 GameKit 0.11.3 `ObjectPool`로 재사용합니다. 430ms 수명 완료, 48개 표시 큐 퇴출, 월드/revision 교체 때 한 번 반납하며 유휴 상한은 48개입니다. 원본 전투 사건·보간 이력과 별도 참조가 남는 `bossHit`은 반납하지 않습니다. 표시·음향·저장 계약은 같고 제품 버전 0.7.26을 유지합니다.

캐릭터는 SVG 원본을 GameKit이 직접 그리는 둥근 씨앗 군단입니다. 병력은 curveSegments 2·strokeArcDivisions 2, 거대개체는 전 종 curveSegments 4·strokeArcDivisions 2로 시작 시 한 번 컴파일하며, 같은 SVG를 쓰더라도 품질별 캐시·메시를 구분합니다. 돌격 완두콩은 압축 후 돌진하고, 곡사 수수알은 껍질을 열어 낟알을 발사하며, 도약 콩알은 배아를 접었다 펴며 도약합니다. 몸·얼굴·팔다리의 표정과 동작은 각 SVG 안에 정의하고 전투 단계는 native vector player로 재생합니다. 거대 밤톨은 `assets/bosses/chestnut.svg`의 몸체·팔 소켓·공격 클립을 사용합니다. 무기 접점은 실제 팔 소켓에서 시작하며 보스 AI와 접촉 판정은 같은 전투 모델이 처리합니다.

아군은 현재 방향에서 병종별 사거리를 확보한 뒤 멈춰 공격합니다. 곡사 수수알은 보스가 너무 가까워지면 물러납니다. 아군 체력바는 개별 현재 HP 합계 / 배치된 모든 유닛의 최대 HP 합계입니다. 전사자도 최대 HP에 포함됩니다. 개별 HP가 판정 기준입니다.

아군은 HP가 0이 되면 짧게 반동을 보이며 옆으로 쓰러지고, 잠깐의 XX 눈 뒤에 기존 SVG의 감은 눈·미소로 편안히 쉽니다. 작은 Z와 느린 호흡을 보이며 등급 외곽선은 유지합니다. 공중이라면 기존 넉백·중력·착지를 마치며 공격·표적·몸체 충돌에서 제외됩니다. 정원에서는 기존 60초 휴식의 경과 비율을 몸 아래 얇은 연보라 막대로 표시하고, 마지막 0.5초에 눈을 뜨며 일어난 뒤 기존 시점에 체력·행동을 회복합니다. 번식 대기에는 이 옆으로 눕는 자세나 수면 막대를 쓰지 않습니다. 영구 손실·전투 수치·저장 형식은 바꾸지 않습니다.

## 화면과 싱글 실행

설정 `#/menu`에는 효과음을 두고, 업그보스전 안에 병종 특성 `#/abilities` 탭을 둡니다. [현재 병종 특성 효과 표](docs/ability-reference.md)는 제품 정의에서 생성하고 정적 검사에서 일치 여부를 확인합니다.

도움말 `#/help`, 농장 `#/farm`, 시작 `#/`는 화면·이력·F5와 동기화됩니다.

`FarmSession`이 GameKit `simloop`의 20Hz 논리 시계로 `Garden`을 진행합니다. 논리 틱 하나에서 전체 경과 시간 0.05초를 한 번 적용하고, AI·먹이·번식·성장·생명주기·스킬·효과 정리와 전체 공간 인덱스 재구축을 한 번 수행합니다. 이동·접촉만 최소 몸체 반경 대비 이동량과 1/60초 상한으로 적응형 하위 단계를 계산합니다. 공격 경로는 기존 스윕 판정을 유지합니다. catchup 상한·저장 직전 입력 반영과 항상 1× 실행은 그대로이며, 프레임마다 물리 빈도를 고정하지 않습니다. 세부 측정 항목은 [시뮬레이션 주기와 성능 진단](docs/performance-diagnostics.md)에 기록합니다. 예전 배속 명령과 저장 값은 이어받지 않습니다. 싱글 실행에는 RoomSession, 전송, 롤백 기록, 네트워크 입력 직렬화를 만들지 않습니다. 시작 manifest에서도 rollback·transport 모듈을 제외합니다. 결정론 난수, 입력, 표시 보간과 진단 모듈은 계속 사용합니다.
표시 프레임은 GameKit `PresentationRuntime`의 단일 샘플을 사용합니다. 20Hz 시뮬레이션과 브라우저 RAF는 같은 단조 시계에 놓이며, 위치·높이·방향·전투 효과·SVG 애니메이션이 같은 표시 시각을 읽습니다. 게임 시계도 동일 프레임에서 샘플링합니다. 입력 어댑터와 수집 배열은 재사용하지만 보간 이력의 값 복사는 GameKit이 소유하며, 개체 교체와 효과 종류 변경은 새 어댑터로 반영합니다. 결정론적 권위 이벤트의 시간은 시뮬레이션 데이터에 유지하고, 화면의 표시 시각은 클라이언트의 GameKit presentation runtime에서 샘플링합니다. 로드·리셋·장면 경계에서는 GameKit revision 계약에 따라 스냅하며 서로 다른 스냅샷을 보간하지 않습니다.

전투에서 나가면 보존해 둔 개인 정원으로 돌아옵니다. 숨겨진 개인 정원은 탭·진행을 누적하지 않습니다.

## 저장과 배포

메인 버전 `0.8.0`의 저장은 `schema: budmori-farm`, `productVersion`, `progress`만 기록하며 기존 키 `bloom-weapon-cards-v4`를 사용합니다. `farm-progress.js`가 디스크 진행 데이터의 단일 계약입니다. 경험치·레벨·미사용 포인트·강화 투자, 종/티어별 보유 수, 누적 먹이 생산 수, 번식·합체 누적 수를 저장합니다. 같은 종·티어·먹이 준비·성장/쿨타임/휴식 상태인 병력은 하나의 수량으로 묶습니다. 진행 중인 성장·번식 대기·60초 휴식은 필요한 남은 시간만 보존하며, 오프라인·일시정지 동안 진행하지 않습니다.

개체 ID·위치·속도·현재 HP·공격/애니메이션 상태·투사체·효과·보스 전투 장면은 저장하지 않습니다. 불러올 때 종/티어 카탈로그로 스탯을 파생하고 병력과 먹이를 새로 배치합니다. 휴식 중인 병력만 남은 시간과 HP 0 상태로 복원합니다. 이미 받은 보상은 보유 수에 포함하고, 수용량 때문에 대기 중인 획득은 확정된 추첨 결과만 보존합니다. 보스 선택 seed·epoch·방문 단계, XP 중복 방지 기록, 보상/원정 완료 watermark와 진행 중 원정 예약을 유지해 재접속이 보상 재추첨·중복 획득을 만들지 않게 합니다. 완료된 전투의 표시 기록은 재생하지 않습니다.

`0.4`–`0.7`의 유효한 `world` 저장은 가져오기 경계에서 검증한 뒤 진행도로 옮깁니다. 실제 소비자는 기존 이용자의 브라우저 저장·내보낸 파일이며, 데이터 손실 없이 `0.8`로 전환하기 위한 단방향 입력 예외입니다. 예전 전투를 실행하는 별도 경로는 없고 새로 쓰는 저장은 항상 `progress`입니다. 기존 저장 지원 종료는 별도 제품 결정 전까지 하지 않습니다. 변환 전 원본은 별도 브라우저 키로 백업하고 시작 화면에서 내보낼 수 있습니다. 이전 `bloom-weapon-cards-v3` 키도 삭제하지 않습니다. 이전 활동 기반 무료 강화 종료 정책은 그대로 적용합니다.

필수 필드가 누락되거나 손상·비호환인 저장은 삭제·덮어쓰지 않고 이어가기를 차단합니다. 원본 백업 실패도 덮어쓰기를 막습니다. 새 정원·가져오기는 명시적 확인 후 기록하며 취소·검증 실패 시 원본을 유지합니다. 다른 탭의 변경은 쓰기 전에 비교해 보호합니다.

영구 진행을 바꾸는 사건만 자동 저장을 예약합니다. 이동·표시 프레임은 저장을 예약하지 않으며, 진행 중인 성장/쿨타임/휴식은 5초 단위의 변경 알림과 화면 이탈 시 저장으로 보존합니다. 저장 경계에서도 진행 데이터가 같으면 JSON 직렬화와 localStorage 쓰기를 생략합니다. 내부 `snapshot/restore`는 원정 정산 등 실행 중 값 복사에만 사용하고 디스크 형식으로 내보내지 않습니다.

이관 후 현재 인원 상한보다 병력이 많아도 기존 병력은 보존합니다. 합체는 완성된 결과 유닛으로 재료를 한 번에 교체하므로 계속 진행할 수 있으며, 새 번식·획득에는 현재 상한을 적용합니다.

기존 GitHub Pages `main /`를 그대로 사용합니다. 머지 후 `node scripts/verify-pages.mjs`가 공개 index·게임·bootstrap의 바이트 수와 SHA256을 비교합니다. 실제 검증·배포 기록은 해당 PR에 남깁니다.

## 소스와 기준

`src/` 폴더 구성:

| 폴더         | 내용                                                               |
| ------------ | ------------------------------------------------------------------ |
| `core/`      | 신호, 공간 격자, 진영 등 모델과 표현이 함께 쓰는 기반              |
| `model/`     | 농장 시뮬레이션, 상태, 진행, 장면·모드, 컬렉션                     |
| `units/`     | 병종 목록, 스탯, 등급, 공격·능력 조합                              |
| `boss/`      | 보스 패턴 수치·동작 조합, 보상                                     |
| `tower/`     | 탑 진행, 조우, 테마, 패시브 표시                                   |
| `save/`      | 저장 형식, 스냅샷 검증·이관, 저장소, 자동 저장                     |
| `render/`    | WebGL 렌더러, 장면·유닛·보스 그리기, 효과, 소켓                    |
| `ui/`        | 도움말, 유물 도크, HUD 집계                                        |
| `app/`       | 로컬 명령과 실행 세션                                              |
| `abilities/` | 능력 정의·진행·상태·성장 화면                                      |
| `formation/` | 편성 스킬 상태·표현·화면                                           |
| `features/`  | 기능 하나의 모델과 표현을 함께 둔 폴더(보스 패턴, 투사체, 성장 등) |
| `styles/`    | 공통 스타일                                                        |

`bootstrap.js`, `farm-app.js`, `showcase.js`, `version.js`, `vector-sockets.js`는 진입점이라 `src/` 바로 아래에 둡니다.

- `src/model/farm-model.js`: 농장, 전방위 자동 AI, 공통 공격 phase, 월드 보스 상태기계·충돌·전투 사건.
- `src/units/unit-abilities.js`, `src/units/unit-attack-capabilities.js`: 종별 공격 수치·능력 조합 registry와 재사용 공격/패시브 capability.
- `src/model/farm-progress.js`: 진행 데이터 추출·검증·그룹 수량 복원과 동일 진행 비교. 디스크 저장의 단일 계약.
- `src/save/farm-snapshot.js`: 실행 중 원정 정산을 위한 명시적인 값 복사. 디스크 저장에는 사용하지 않습니다.

## SVG 원본 시작 로딩

캐릭터 배포 리소스는 `assets/troops/*.svg` 원본만 사용합니다.
부트스트랩이 manifest의 SHA-256/크기를 확인하고 GameKit `vector-assets-loader`로 시작 시 한 번 변환한 뒤 게임을 시작합니다.
메시와 애니메이션은 세션 캐시에서 재사용하며 장면 전환·매 프레임에 다시 컴파일하지 않습니다.
일반 병력은 `smallAsset`(곡선 분할 2, 선 끝 호 분할 2), 모든 거대 보스는 `standard`(4, 2) 품질로 별도 변환합니다. 보스는 같은 병종의 SVG를 `standard` 품질로 변환해 씁니다.
생성 정점 배열/base64 메시를 HTML에 내장하거나 생성 캐릭터 파일을 배포하지 않습니다.
리소스 로딩 실패 시 시작을 막고 재시도 UI를 제공합니다. `npm run check`는 원본 모듈 graph와 SVG/manifest 기록을 검증하며, 기본 Farm E2E는 실제 브라우저에서 게임 리소스가 로드되는 시작 흐름을 확인합니다.

자동 저장은 변경이 멈춘 뒤 1초, 계속 변경될 때는 최대 10초에 체크포인트를 저장합니다. 기존 타이머가 최신 마감 시각을 다시 확인해 매 틱 취소·재생성하지 않습니다. 스냅샷의 정규화·검증·저장 순서와 실패 시 기존 저장 보존은 유지합니다. 물리 스텝은 비직렬화 임시 배열을 재사용하되 시작 시점의 유닛 순서를 고정하며, 도중 생성된 유닛은 인덱스에 즉시 반영되고 다음 스텝부터 진행합니다.

### SVG 입·지면 좌표 계약

모든 병종과 보스 SVG는 `mouth`와 `ground` socket을 명시합니다. `mouth`는 공격 표정의 입 중앙이며 `body` part를 따르고, 얼굴 anchor는 `face-eye-left`·`face-eye-right`·`face-mouth` socket(모두 `body`)이며, `ground`는 몸통이 움직여도 월드 그림자 기준을 고정하는 정적 canvas 좌표입니다. 원본 SVG transform은 컴파일 geometry에 이미 반영되므로 socket에 다시 적용하지 않습니다. 누락·잘못된 좌표는 원본 검증과 시작 시 asset/species를 포함한 오류로 중단하며 다른 병종이나 viewBox 값으로 대체하지 않습니다.

시작에 한 번 읽은 compiled metadata와 native GameKit asset에서 모델·렌더가 같은 socket 계약을 사용합니다. 모델은 소환을 실제로 방출할 때만 별도 runtime player를 phase seek하여 애니메이션된 입을 읽습니다. 렌더의 소환도 동일 phase seek와 몸통 pose를 사용하며 이전 프레임의 crossfade나 피격 장식 변형에 의존하지 않습니다. 화면을 향한 보스 SVG의 가로축은 월드 x, 세로축은 기존 0.785 높이 투영으로 바꾸고 현재 보스 높이를 더합니다. 지면 기준은 애니메이션된 ground socket으로 흔들지 않습니다.

asset/player는 세션 runtime에만 보관하고 저장에 넣지 않습니다. 저장 복원은 기존 패턴 phase·elapsed·released로 다음 방출 좌표를 다시 계산합니다. 소환 간격·개수·전투 스탯과 저장 schema는 그대로입니다.

## 코드 규약 확인

[코드 규약](docs/code-conventions.md)을 따릅니다. `npm run format`은 직접 작성한 소스·스크립트·기존 E2E·문서의 포맷을 적용하고, `npm run format:check`와 `npm run lint`는 파일을 고치지 않고 위반을 검사합니다. `npm run check`는 두 검사와 원본 엔트리 검증을 실행하며 어떠한 제품 파일도 생성하지 않습니다. 고정 vendor는 직접 포맷하지 않습니다.

## 화면 밖 렌더링·집계·충돌 성능

화면 밖 병력도 계속 전투하고 애니메이션 시간을 유지하며, HUD 체력은 기존 표시 보간을 사용합니다. 큰 보스·부착물·무기 궤적 등 경계가 독립적인 표현은 보수적으로 계속 그립니다.
