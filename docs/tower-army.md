# 100층 탑과 전선 · 예비대

## 플레이 계약

- 탑은 100층에서 끝납니다. 100층은 여러 수호자 뒤에 최종 보스가 등장하며, 전원 처치 후 정상 장면으로 이어집니다. 정상 장면은 8초이며 건너뛸 수 있습니다.
- 병종 XP와 별도로 층 전투를 클리어하면 전체 성장 XP를 얻습니다. 전체 레벨로 농장 최대 정원이 늘며, 최고 정원은 1,000마리입니다.
- 전선은 **보유 수가 아닌 농장 최대 정원의 절반**입니다. 등급과 무관하게 한 마리가 한 슬롯을 차지합니다. 층 시작 때 상한을 고정하고 정원 성장분은 다음 전투부터 적용합니다. 최대 전선은 일반 병력 500마리이며 복사·분열체 등 전투 소환물은 제외합니다.
- 나머지 병력은 예비대입니다. 기존 병종 투입 순서대로 처음 배치하고 전사자 자리를 자동 보충합니다. 앞 병종이 소진되면 다음 병종을 사용하며 병종별 고정 정원은 없습니다. 초기 배치는 수에 비례한 묶음으로 약 1.5초 안에 완료합니다.
- 교전·산개·후퇴는 하나만 선택되는 지속 명령입니다. 현재 병력과 이후 예비대에 함께 적용되고 기본은 교전입니다. 산개는 실제 간격을 넓히면서 공격하고, 후퇴는 공격·추격을 멈추고 여러 적과 벽을 고려해 이동합니다. 명령에 스탯 보너스는 없습니다.
- 후퇴는 아직 발동하지 않은 **기본 공격 준비**만 즉시 취소합니다. 발사한 투사체, 이미 시작한 도약 및 고유 기술의 확정 동작을 되돌리지 않습니다. 교전을 다시 누르면 전투를 재개합니다.
- 산개도 전환 시 아직 발동하지 않은 기본 공격 준비를 양보합니다. 이후 매 논리 틱에 boid의 분리(separation) 조향을 적용합니다. 간격(`병력 반경 + 이웃 반경 + scatterGap`) 안으로 들어온 같은 편 이웃마다 겹친 정도에 비례한 밀어내는 벡터를 더하고, 사거리 밖이면 적을 향한 접근 벡터를 약하게 섞어 그 방향으로 움직입니다. 밀어내는 힘이 거의 없거나 이미 사거리 안에서 공격할 준비가 된 병력은 교전과 같은 흐름으로 공격합니다. 공격이 끝난 뒤의 후딜 동안에는 병력이 멈춰 있지 않고 계속 분리 이동하므로, 이미 공격하던 병력도 퍼지고 사거리 밖으로 밀려난 병력은 그만큼 공격하지 못합니다. 공격 차례 배분이나 순환 횟수는 없으며 병력 전체가 같은 규칙을 씁니다. 사거리·이동 속도·피해량·이미 시작한 공격과 도약은 그대로입니다. 간격을 비우는 동안은 공격하지 못하므로 밀집한 병력은 퍼진 뒤에 공격합니다.
- 층마다 유한한 보스 명단이 있습니다. 명단의 보스는 전투 시작에 경기장 중앙에서 0.5초 간격으로 차례로 솟아올라, 중앙 근처에 서로 붙어 한 무리로 떨어집니다(중심 간격 = 보스 반지름 × 2.2, 1마리면 중앙). 모두 착지하면 전투가 시작됩니다. 무리는 무리 중심에 가장 가까운 병력을 함께 노려 같은 곳으로 함께 밀고 들어가므로, 병력이 여러 보스를 동시에 상대하게 되어 한 마리씩 차례로 잡히는 각개격파를 막습니다(`bossPackTarget`). 마지막 층의 최종 보스는 앞선 수호자를 모두 처치한 뒤에만 중앙에 등장합니다.
- 소환: 보스가 소환을 고르면 예열 시작에 피해 없는 충격파(보스 몸 가장자리 + 7.2, 넉백 13·띄움 5.1)로 주변 병력을 밀어낸 뒤, 비운 자리에 부하 2마리를 뱉습니다. 소환은 범위 패턴 차례가 오면 우선 선택되고(쿨다운 10초), 보스 체력 75% 이하부터 씁니다. 살아 있는 부하는 살아 있는 보스 1마리당 최대 2마리입니다.
- 부하는 보스를 거대 유닛 크기로 줄인 적입니다: 몸 = 소환한 종 T1 × 6(거대화 크기, 거대화 방어 보너스 포함), 체력 = 소환한 보스 최대 체력 × 0.05, 공격력 × 0.25. 평타 대신 소환한 보스의 속성 고유기를 보스 범위의 0.5배·쿨다운 2배로 씁니다. 같은 예고 표시가 보이며, 시전 중에는 멈춰 섭니다. 시전 진행 상태는 저장하지 않아 새로고침하면 대기 상태로 다시 시작합니다. 부하의 명중은 보스 유물을 충전하지 않습니다.
- 보스는 각자 속성 하나만 씁니다. 21층부터 물 보스와 풀 보스, 41층부터 물·풀·불 보스처럼 지나온 구간 속성의 보스가 함께 나옵니다. 속성은 적 유닛의 `enemyElement`가 원본이며(부하는 소환한 보스를 따름), 고유 기술 사용 조건·아군 공격 상성·얼굴과 머리 위 표식이 모두 이 값을 읽습니다.
- 층 보상은 명단 전체 처치 후 한 번입니다. 병종 XP·획득 보상의 기존 총예산도 한 번만 정산하며 보스 수만큼 복제하지 않습니다. 기존 강화층의 내 카드 선택과 보스 진영 카드 선택은 그대로 한 번씩입니다.
- 최고 시작층은 `max(1, 최고층 - ceil(최고층 × 0.2))`입니다. 최고층 50이면 40층, 100이면 80층이며 더 낮은 시작층도 자유롭게 선택합니다. 첫 무카드 전투를 위한 준비 난도와 기존 강화층 경로를 유지합니다.
- 목표 플레이 길이는 **선택한 시작층부터 이번 도전 종료까지 5–15분**입니다. 전체 1–100층을 강제로 압축하거나 타임아웃으로 끝내지 않습니다. 전투가 길어지면 기존 격노 규칙이 적용됩니다.
- 입구·정원·무기고·왕실 홀·테라스는 시각 테마입니다. 환경 피해, 감속, 낙하 위험이나 새 경로 장애물은 없습니다. 명령은 보스의 예고된 패턴에 대응하기 위한 조작입니다.
- 다음 전투의 생존자 완전 회복, 전사자의 등급별 층 휴식, 기존 경로와 강화 카드 빈도를 유지합니다.

## 전장과 카메라

전장 외곽은 69×51(반경 34.5×25.5)이며 `CONFIG.farm.tower.arena`가 모델과 홀 표현의 공통 원본입니다. 야외 농장 46×34, 탑 문, 복귀 배출 지점은 기존대로입니다. 보스·병력의 접촉과 이동, 돌진·도약 예고도 실제 전장 경계를 사용하며 공격 사거리와 예비대 투입 간격은 늘리지 않습니다.

농장과 전장은 같은 캔버스 제스처를 사용합니다. 한 손가락/마우스 드래그로 패닝하고 두 손가락/휠로 줌합니다. 핀치는 기존 중심 아래의 월드를 새 중심에 유지하며 손가락 추가·해제 때 기준을 다시 잡습니다. 캔버스 밖 UI의 스크롤·라디오·카드는 카메라 입력이 아닙니다. 모달·컷신·장면 이동·회전·포커스 상실 시 캡처를 정리합니다.

전장 기본 보기는 기존 46×34 시점과 공중 효과 여백을 사용합니다. 확장된 바닥 전체에 강제로 맞추지 않으며, 직접 조작한 카메라는 효과 생성으로 움직이지 않습니다. 새 층 진입은 기본 자동 프레이밍으로 돌아갑니다. 카메라는 저장·전투 상태를 변경하지 않습니다.

검증: `node tests/battle-camera.e2e.mjs desktop|portrait|landscape`를 각 화면별로 실행합니다. 실제 브라우저 포인터·CDP 터치, 같은 actor 시점의 전후 캡처와 전체 체크포인트, 경계·복귀·회전·모달 취소를 확인합니다. 소프트웨어 렌더링 결과는 물리 모바일 FPS가 아닙니다.

## 저장과 보상

기존 보유 병력·병종 투자·최고층을 보존합니다. 디스크에는 농장과 완료된 영구 진행만 저장하며, 새로고침하면 농장으로 돌아옵니다. 전투 중 이어하기는 추가하지 않습니다.

전체 XP는 현재 도전 번호와 마지막 정산층의 영구 워터마크로 중복 지급을 막습니다. 병종 보상은 기존 encounter 영수증을 사용합니다. 정상 장면에 들어가기 전에 두 정산을 확정하고 자동 저장을 즉시 시도합니다. 저장 실패는 기존 저장 알림으로 표시하며, 건너뛰기는 보상을 다시 정산하지 않습니다. 진행 중인 획득 상자 계산도 기존 저장 계약에 포함됩니다.

내부 세션 체크포인트는 디스크 저장과 다릅니다. 보스 배열, 실제 Unit의 공격 상태·ID·generation, 전선·예비대 및 도전 상태를 재수화합니다. 디스크 진행 저장 형식은 바꾸지 않습니다. 이는 런 이어하기 UI가 아닙니다.

## 검증 명령

- `npm run check`: 정적 소스·자산·모듈 계약
- `npm run test:source-smoke`: 기존 혼합 전투·보스 기본 공격·카드 흐름
- `npm run test:tower-army`: 500 전선, 명령, 유한 증원, 정상 장면·저장 복구의 고정 사용자 흐름
- `npm run test:scatter-command -- 100 1 center`: 같은 체크포인트·카메라의 교전/산개를 0.5/2/5/10초에 비교합니다. 첫 인자는 100/250/500, 둘째는 1/3 보스, 셋째는 center/wall입니다. 5/10초 실제 PNG와 최근접 거리·몸체 간격·중앙 80% 점유 면적·보스별 밀집도·모델 틱 시간을 기록합니다. 100/500-1-center는 반복 명령·사거리·예비대도 검사합니다. 제품 세션 복원과 실제 시간 진행으로 장면 페이드를 끝낸 뒤 실제 바닥·병력·보스 그리기와 framebuffer 픽셀을 확인합니다. 이 계측은 PNG 시각 검토를 대체하지 않습니다.

산개 조향은 [Reynolds의 조향 행동 연구](https://www.red3d.com/cwr/steer/gdc99/)의 분리(separation)와 접근(seek)을 현재 모델에 적용합니다. 기존 접촉 해소는 유지합니다. 별도 진형 좌표나 렌더 위치 보정은 없습니다.

브라우저 검증은 각 실행 180초 이내이며, GitHub Chromium SwiftShader 결과는 실제 기기의 FPS 측정과 구분합니다. 상세 실행 결과·커밋·화면은 해당 PR에 기록합니다.
