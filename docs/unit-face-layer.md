# 얼굴 레이어

기준 버전: `0.67.8`.

## 구조

병종 SVG는 몸체만 그립니다. 표정은 모든 병종이 같은 규칙으로 만드는 **얼굴 레이어**이며 몸 위에 얹어 그립니다.

- 병종마다 가진 얼굴 자원은 `body` part의 socket 세 개뿐입니다: `face-eye-left`, `face-eye-right`, `face-mouth`.
  눈 크기·입 폭·볼 위치는 두 눈 사이 간격에 비례해 정해집니다.
- `src/units/face-layer.js`는 socket 세 점에서 상태 표정 8종(중립·웃음·집중·공격·놀람·아픔·배고픔·기절)과 성향 표정 5종(느긋·소심·발끈·까불·다정)을 베지어 경로로 만듭니다. 순수 함수이며 SVG 캔버스 좌표를 씁니다.
- `src/render/unit-face-draw.js`는 몸이 그려진 직후 현재 자세의 socket 세 점으로 anchor 삼각형을 변환해 그립니다. 찌그러짐·기울기·튀어오름이 몸과 함께 움직이고, 몸이 스프라이트이든 native 벡터이든 같은 경로입니다.
- 얼굴은 표정 13종 × 눈·눈·입 3개, 흰 볼 1개, 속성 표시 5개인 45개 공유 이미지로 조합합니다. 시작과 그래픽 복구 때만 아틀라스에 올립니다. 확대 시 원본 벡터와 초상화에서는 같은 색의 연속 경로를 하나로 합칩니다. 서로 겹치는 도형의 순서(눈 위의 하이라이트, 입 위의 이빨)는 바뀌지 않습니다.
- UI 초상화(`species-paint.js`)는 같은 경로를 SVG `path`로 바꿔 몸 SVG 끝에 `face-layer` 그룹 하나로 붙입니다.

## 깊이와 배치

기본 병력10종과 호두 방어 변형은 모두 불투명 아트입니다. 정적 음영·골·하이라이트22개 중21개를 미리 합성한 RGB로 바꾸고, 몸통 밖의 땅콩 장식1개는 삭제했습니다. 밀·보리의 넘친 음영 경로는 몸 안으로 줄였습니다. SVG 원본을 수정하며 몸통 이미지나 조합별 atlas를 만들지 않습니다. 몸통 윤곽·소켓·충돌 치수는 유지합니다.

땅콩은786개의 authored opacity key를 제거했습니다. 숨기거나 나타내던 부품은 두 축 크기를0으로 접고 펼칩니다. 계속 불투명했던 부품의 scale key는 그대로 두며, clip 길이·키프레임 시점·이동·회전은 바꾸지 않습니다. 이 때문에 일부 껍질 전환은 페이드 대신 크기 전환으로 보입니다. GameKit0.40.3은 authored/base pose의 유한한 scale0을 허용하고 기존 GPU/CPU 계산을 그대로 사용합니다.

`vector-sources.cjs`가 새 반투명 paint나 opacity clip을 거부하며, 실제 WebGL 깊이 시나리오는 vertex alpha0/1·11개 불투명 variant·일반 clip에 opacity channel이 없음을 검사합니다. 분신(alpha0.52), 게임 효과의 fade와 이미지 가장자리 커버리지는 별도 표현 경로입니다.

몸통을 병력마다 얼굴과 번갈아 제출하지 않습니다. GameKit `hasOpaqueCoverage`가 같은 part의 불투명 영역 안에 반투명 장식까지 포함됨을 증명한 메시만 병종·몸 변형별로 먼저 제출하고, 깊이를 기록합니다. 판정은 시작할 때 geometry/expression별로 한 번 캐시합니다. 전환·부위 opacity는 actor의 `hasOpacityChannel`·`hasNonUnitBaseOpacity` 계약을 사용합니다.

그 뒤 얼굴·속성·전후 링·시설·투사체·보스 등을 원래 actor 순서로 제출하며 깊이 검사만 합니다. 각 actor의 뒤/몸통/앞 순위를 서로 겹치지 않는 깊이 슬롯에 둡니다. 분신과 외부 효과로 투명도가 적용된 몸통은 이 순서 안에서 몸통과 얼굴을 함께 합성합니다. 원본 아트나 45개 공유 얼굴 부품을 조합 수만큼 다시 굽지 않습니다. GameKit의 `orderedMeshQuads`가 이 반투명 몸통과 뒤따르는 얼굴 이미지를 같은 indexed stream에 원래 순서대로 담습니다. 호환되는 번식·합성 표식과 일반 벡터 도형도 같은 순서 안에서 합칩니다. 같은 스타일의 도형은 좌표·UV와 공유 스타일 명령을 나눠 보내고, 캐시는 사용 길이가 바뀌어도 할당된 용량을 재사용합니다. 몸통 정점은 한 번 보관하고, 같은 chunk의 정점 참조·index는 순서가 바뀌지 않으면 다시 올리지 않습니다. 불투명 몸통은 기존 instancing을 유지하고, 깊이·clip·stencil·표현 기능이 달라지면 해당 경계에서 제출합니다.

`tests/unit-depth-batching-scenario.js`는 같은 DTO·표시 시각에서 ordered 배치를 끈 원래 actor 순서와 현재 SDK의 단순 painter 경로·묶은 제출의 실제 WebGL 픽셀을 비교합니다. 원래 기준 대비 제출 감소 조건은 유지하고, 새 단순 painter 경로의 draw도 별도로 기록합니다. `npm run test:unit-sprites`의 native 벡터 흐름에서 실행합니다. 비용 측정과 환경 한계는 [성능 진단](./performance-diagnostics.md)에 기록합니다.

## 선택 규칙

`unitLook(state, temperament)`는 몸 변형과 얼굴을 따로 돌려줍니다. 몸 변형은 `neutral`과 호두의 `guard`(껍질 속)뿐이고 `player.setExpression`에는 이것만 보냅니다. 성향 얼굴은 다른 상태가 없을 때만 보이며, 전투·피격·공중·배고픔·웃음·수면·사망 표정이 항상 우선합니다. 적과 성장 중 새싹은 성향 얼굴 없이 중립 얼굴을 씁니다. `sleep`은 웃음 얼굴, `guard-attack`은 몸 변형 없이 공격 얼굴입니다. 성향 이름은 `lineage.js`의 `TEMPERAMENTS`이며 id와 능력치·패시브는 그대로입니다.

## 스프라이트

기본은 native 벡터입니다. 선택한 sprite 모드에서는 몸에 얼굴이 없으므로 모션마다 몸 한 장만 굽습니다(이전에는 모션 × 표정 조합 421장). 속성 색도 얼굴의 볼 색이라 속성 유닛도 스프라이트 몸체를 씁니다. 복제 유닛(삼각형 알파)과 확대, 호두 방어 변형 등은 원본 벡터로 표현합니다.

## 검증 범위

깊이 배치는 9개 고정 장면에서 원래 actor 순서와 실제 픽셀 차이 0을 확인합니다. `tests/unit-face-composition.mjs`는 10종 × 13얼굴이 세 socket만으로 생성·구분되고 몸 안에 있음을 확인합니다. 브라우저 검증(`test:palette`, `test:unit-sprites`, `test:codex`)은 소프트웨어 GL 환경이며, 실제 기기 프레임 비용과 작은 크기에서의 표정 판별은 검증하지 않았습니다.
