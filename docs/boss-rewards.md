# 보스 승리 보상

## 승인한 규칙

보스를 이길 때마다 상자 하나의 수량을 한 번 추첨합니다. 상자를 여는 행동은 이미 정산된 결과를 보여주며, 다시 열거나 건너뛰어도 추가 추첨·추가 지급이 없습니다. 보상은 기존과 같이 1단계 씨앗 5종 중 한 종이며 농장 먹이로 자랍니다.

기준 수량 `E = ceil(층 / 10) × 층 종류 보상 배율 × 신기록 배율`입니다. 층 종류는 일반 ×1, 정예 ×2, 중간 보스 ×3이며 이전 최고층보다 높은 층을 처음 깨면 ×2입니다. 경험치와 보스 체력·공격력 계산은 바뀌지 않습니다.

| 결과      | 확률 | 실제 수량     |
| --------- | ---- | ------------- |
| 꽝        | 5%   | 0             |
| 매우 적음 | 10%  | round(E / 3)  |
| 적음      | 20%  | round(2E / 3) |
| 보통      | 30%  | E             |
| 많음      | 20%  | round(4E / 3) |
| 매우 많음 | 10%  | round(5E / 3) |
| 대박      | 5%   | 2E            |

정수 반올림으로 낮은 층에서는 이웃 결과의 수량이 같을 수 있습니다. 대칭 가중치와 3분의 1 간격으로 평균은 E입니다. 신기록이 아닌 20층 중간 보스는 E=6으로 `0/2/4/6/8/10/12`, 40층 중간 보스는 E=12로 `0/4/8/12/16/20/24`입니다. 처음 얻는 종도 같은 분포를 사용하며 표시 수량 밖에 짝을 추가하지 않습니다.

## 연출과 지급

2026-11-01 사용자가 검토한 시안처럼 약 1초 동안 상자를 움츠렸다가 열고, 새싹이 부채꼴로 튀어나와 앞쪽에 통통 착지합니다. 0마리는 빈 상자와 안내를 보여줍니다. 연출용 새싹은 최대 24개이고 실제 수량은 별도 숫자로 정확히 표시합니다. 수량이 많아도 연출 시간이 늘어나지 않습니다. 결과 바로 보기·닫기·Escape로 기다림을 끝낼 수 있습니다. 모션 감소 설정에서는 이동 연출을 생략합니다.

지급은 상자 연출과 독립입니다. `freeRoom()`이 허용하는 만큼 농장에 배치하며 나머지는 보상 대기열에 남깁니다. 영수증의 획득량은 항상 `배치량 + 대기량`이고, 대기열 합계는 각 영수증 대기량 합계와 같습니다. 저장·복원과 반복 정산으로 권리가 사라지거나 늘어나지 않습니다.

## 모델·저장 계약

- `src/boss/boss-rewards.js`가 분포·층별 기준·추첨·영수증·지급의 원본입니다. 기존 GameKit `SeededPRNG.nextUint32()`를 정확히 한 번 호출하고 7개 누적 구간 중 하나를 고릅니다. 작업량은 층과 수량에 관계없이 최대 7개 구간 비교입니다.
- `settleBossKill(world, {encounterId, stage, species, kindReward, record})`는 RNG·대기열·영수증·정산 워터마크를 한 동기 작업으로 확정합니다. 같은 전투 영수증은 재사용하며 워터마크 이전 전투는 재추첨하지 않습니다.
- 영수증은 기준 수량·결과 구간·획득/배치/대기 수량·공개 여부를 보관합니다. 공개는 `revealBossReward()`를 거치며 수량·난수에는 영향을 주지 않습니다.
- 저장 이관 경계에서만 예전 PRD 계산을 남은 작업부터 완료하고 이미 획득한 수량과 대기 권리를 보존합니다. 이관된 영수증은 `bandIndex:null`, `baseAmount:0`으로 표시해 새 분포로 재해석하지 않습니다. 새 전투 경로에는 예전 확률·상자 분할·PRD 작업이 없습니다.
- 예전 PRD 코드를 유지하는 범위는 `src/save/boss-reward-ledger.js`의 저장 schema 1·기존 내보내기 파일·이전 런타임 체크포인트 이관뿐입니다. 기존 저장 지원을 명시적으로 종료할 때 제거합니다. 새 정산이나 틱에서는 호출하지 않습니다(PM-004).
- 저장 schema는 2이며 GameKit 0.40.0의 공식 이관 API를 사용합니다. 읽는 중 이관에 실패하면 원래 오류를 `cause`에 남긴 `SaveError('unreadable')`로 쓰기를 잠가 원본을 보호합니다. 공통 수정은 [SDK PR #182](https://github.com/byh-playground/bloom-gamekit/pull/182)에 있습니다.

## 결정 근거와 확인할 사례

요구사항은 단일 개봉·확률 기반 넓은 7단계 분포·개별 추첨 제거이며 위 확률/수량과 연출 시안은 사용자가 승인했습니다(AI-004·AI-008). 누적 가중치로 한 결과를 선택하는 방식은 [Python 공식 `random.choices` 문서](https://docs.python.org/3/library/random.html#random.choices)의 상대 가중치/누적 가중치 설명과 비교했습니다(조회 2026-11-01). 고정 SDK에는 가중 선택 API가 없어 게임 고유의 7개 보상 구간만 제품 계층에 둡니다. 공통 난수 생성기는 그대로 사용합니다(DEV-001·AI-009).

검증 사례는 40층 중간 보스의 0/12/24마리 결과, 한 번 공개/건너뛰기/재열기 후 수량 불변, 미보유 종의 숨은 추가 지급 없음, 공간 부족 대기→저장/복원→배치, 같은 전투 중복 정산, 구 저장의 계산 중/정산 완료 보존입니다. 시각 확인은 고정 뷰포트에서 시작·중간·착지와 0마리 장면을 직접 캡처합니다(AI-005·AI-013·AI-015·AI-017).
