# 다국어(i18n) 계약 — 한국어 `ko` · 영어 `en`

#SSOT #MECE #Ubiquitous-Language #Dependency-Inversion

## 1. 언어 결정 (페이지 로드마다 1회)

```js
// src/i18n/locale.js — GameKit i18n 모듈(고정 dist, 해시 검증 로드)로 만든 페이지 로캘 1개
export const LOCALE = createLocale({ locales: ['ko', 'en'], fallback: 'en', storageKey: 'budmori-locale', isolated });
//   ?lang=ko|en  →  저장한 선택(localStorage 'budmori-locale')  →  브라우저 언어 첫 일치(ko-KR → ko)  →  'en'
// 격리 장면(?help= / ?lab= / ?showcaseDemo=1)은 저장한 선택을 읽지도 쓰지도 않는다.
LOCALE.choose(locale); // 저장 → ?lang=locale 로 새로고침. 런타임 재번역 경로는 없다(KISS).
```

`locale.js`는 맨 위에서 i18n 번들을 top-level await로 받는다(`src/gamekit-module.js`). 가장 먼저 여는 모듈의 로딩
문구부터 플레이어 언어여야 하기 때문이다. bootstrap은 같은 검증 로드를 재사용하므로 번들을 두 번 받지 않는다.
i18n 번들을 받지 못하면(첫 방문 오프라인·CDN 장애) 문구를 쓰는 모듈이 모두 멈추고 `index.html`의 정적 화면이 남는다.

| 상황           | 언어 전환                                                                  |
| -------------- | -------------------------------------------------------------------------- |
| 메인 화면·농장 | 설정 → 언어 선택 → 저장(pagehide) 후 새로고침                              |
| 탑 도전 중     | 선택 불가, 사유 표시. 도전 런은 메모리에만 있어 새로고침으로 사라지기 때문 |

## 2. 텍스트 원본 = TextPair (언어 짝을 한 객체에)

```js
// 고정 문구
{ ko: '낙뢰', en: 'Lightning' }
// 값이 들어가는 문구: 언어마다 어순·조사·복수형을 직접 소유한다. 인자는 이름 있는 값 객체 1개.
{ ko: ({ count }) => `새싹 ${LOCALE.number(count)}마리`,
  en: ({ count }) => `${LOCALE.number(count)} ${LOCALE.plural(count, { one: 'sprout', other: 'sprouts' })}` }
```

| 위치                                              | 형태                                                                   | 해석                                                                                                                                                                                                              |
| ------------------------------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 모델 정의(`MODEL_FILES`, 예: 병종·유물·카드 정의) | 정의 데이터 안에 TextPair 그대로 (`name: { ko, en }`)                  | 모델은 `src/i18n/` 를 import하지 못함(lint 경계, DEV-006). 화면 코드가 `LOCALE.text(def.name)`                                                                                                                    |
| 화면 코드(UI·렌더·앱)                             | `src/i18n/messages/<영역>.js`의 `LOCALE.messages({ key: { ko, en } })` | `MESSAGES.key(values)`                                                                                                                                                                                            |
| `index.html` 정적 문구                            | 요소에 `data-i18n="key"`(textContent) / `data-i18n-<속성>="key"`       | `startup-loading.js`(index.html이 가장 먼저 여는 모듈) 맨 위에서 `LOCALE.applyPage(document, PAGE)` 1회. 로딩 패널 요소는 빈 칸으로 두어 다른 언어가 한 프레임 비치지 않게 한다. 키는 `src/i18n/messages/page.js` |

- `data-i18n`은 textContent를 통째로 바꾸므로 자식 요소가 없는 말단 요소에만 붙인다(아이콘·숫자와 섞이면 `<span>`으로 감싼다).
- 숫자는 `LOCALE.number(n)`(로캘 구분자). `toLocaleString('ko-KR')` 직접 호출 금지.

오타 키(`MESSAGES.nmae`)와 한쪽 언어가 빠진 짝은 정의·호출 시점에 예외를 던진다(GameKit i18n 계약).

## 3. 강제 규칙 (`npm run lint` → `project/localized-text`)

```text
허용: 한글 리터럴이 { ko: …, en: … } 객체의 ko 멤버 안에 있다
허용: new XxxError(…) / XxxError(…) 인자 (개발자 진단)
제외 파일: src/debug/** (장면 연구실), src/core/performance-diagnostics.js (채팅에 붙여 넣는 개발자 진단 보고)
그 외 한글 리터럴 → 오류
```

`index.html`의 한글은 `<noscript>` 안에서만 허용(`scripts/source-graph.mjs` 검사). `<head>`의 메타·제목과 `manifest.webmanifest`는 크롤러·설치 화면이 JS 없이 읽으므로 기본 언어 `en` 1개로 둔다.
