# 먹이 배분·예약·자동 생산

## 결정과 적용 범위

사용자 요구는 새싹 성장 우선, 눈앞 먹이 섭취, 원거리 중복 추격 방지, 1,000마리 성능 보존이다. 최초 기준본은 `78bda25ab7ad55c6b86c9d3a69fc542be62ed97d`(0.67.11)이며, 작업 중 추가된 다국어 지원·Pages 복구를 보존해 최종 통합·비교 기준은 `9353f0360735334239d84409e44a2b8f964d6a10`(0.67.12)이다. 이전 미푸시 초기 커밋은 복구되지 않아 이 기준에서 구현했다.

조사·비교한 일차 자료는 [고정 SDK scheduler 원본](https://github.com/byh-playground/bloom-gamekit/blob/f0df18d64dfec77227200494f43419821b34aaf3/modules/work-scheduler/index.js), 로컬 `vendor/upstream/work-scheduler.js`, 기존 `farm-food-field.js`의 공간 그리드·검색 스냅샷이다. SDK는 제한된 작업 실행을 소유하고 식사 자격·분배 정책은 게임이 소유한다. 이번 변경도 SDK·논리 20Hz·물리 갱신 규칙을 유지한다(AI-003, AI-004, AI-009, AI-012).

## 식사와 다음 한 끼

```js
섭취반경 = Math.max(0.42, unit.radius + 0.1);
원거리목표 = 병력당 1개, 먹이당 1명;
새싹보호량 = 식사준비된새싹중다음한끼배정이없는수;
```

- `FoodReservations`가 이동 예약·새싹 보호 풀·비행 중 배정·근접 섭취 결정을 소유한다. 기존 병력/먹이 객체를 빌리며 영구 ID를 추가하지 않는다(DEV-001).
- 식사 준비된 새싹의 다음 한 끼부터 보호한다. 검색 큐가 아직 처리되지 않아도 보호 풀은 성체가 소비·예약할 수 없다. 부족하면 성체의 이동 예약을 회수한다. 이후 두 끼를 미리 예약하지 않는다.
- 새싹이 한 끼를 먹거나 사망·성장·합성·일꾼 전환 등으로 자격을 잃으면 기존 배정/검색을 해제하고 보호량을 조정한다. 배부름·식사 대기·일꾼·기절·공중·사망·성장 중 성체·합성 재료를 제외한다.
- 근접 섭취는 먹이 중심의 기존 병력 공간 인덱스 조회로 결정한다. 도착한 새싹 예약자를 보호하고, 그 외에는 새싹을 우선한다. 새싹 몫을 성체가 가져갈 수 없다. 이미 배정된 새싹 몫은 해당 새싹이 먹고, 아직 소유자가 없는 보호 풀은 식사 진행이 적은 근처 새싹부터 먹는다.
- 성체끼리는 섭취 범위에 도착한 예약자가 우선이다. 예약자가 멀리 있으면 가까운 식사 가능 성체가 먹는다. 거리 동률은 병력 ID 순이다. 한 병력은 한 틱에 한 끼만 먹으며 소비자와 기존 예약자 양쪽 검색을 취소한다.
- 더 가까운 먹이가 생겼다는 이유로 유효한 원거리 목표를 바꾸지 않는다. 기존 정체 2.5초/진행 0.08m/총 8초 lease와 이동 속도 기준 6초 거리 제한은 유지한다.

## 자동 생산과 더미

자동 생산은 실제 `FarmSession.advance → Garden.advanceWork → stepWork → impact → spawnFood` 경로를 사용한다. 새싹 배달 목적지는 `spawnFood`의 `automatic` 옵션으로 구분한다. 다음 한 끼 배정이 없는 식사 가능 새싹을 순서대로 선택하고, 실제 생성에 성공한 먹이만 비행 단계부터 배정한다. flight/bounce도 배정으로 세어 중복 배달하지 않는다. 대상 부적격 시 배정을 해제해 남은 먹이를 재분배한다. 사각 농장에서는 타원 투영을 적용하지 않고 안전 경계만 보정해 구석의 자동 배달과 수동 클릭 좌표를 모두 유지한다. 준비된 미배정 새싹이 없으면 기존처럼 생산 더미 주변에 떨어뜨린다. 수동 먹이는 클릭 좌표와 기존 경기장 경계 보정을 유지한다. 기존 초당 생산력·등급 배율·창고 상한은 바꾸지 않는다.

```js
목표더미수 = Math.ceil(실제먹이일꾼수 / 20);
실제더미수 = Math.min(목표더미수, 간격을유지하는배치가능자리수);
최소중심간격 = CONFIG.farm.work.pileWidth * 3;
분당생산력 = 실제배정병력별생산력의합 * 60;
```

작업 영역의 고정 후보 자리 중 기존 더미와 가장 먼 곳부터 추가한다. 첫 자리는 중앙에 가까운 곳을 고른다. 기존 위치는 유지하며 목표 수가 바뀔 때만 자리 선택을 실행한다. 공간 부족 시 간격을 좁히지 않는다. 빈 더미는 기존 대기 후 같은 위치에 보충된다. 인원·등급 변경 시 배정과 생산력은 별도로 갱신하고 병력을 균등하게 나눈다. 더미 그림의 최대 폭(식량 가득·피격 squash 포함)과 간격은 같은 설정에서 파생한다(DEV-013).

## 비용과 계측

기존 원거리 검색은 링/버킷·제한적 fallback·검색 큐와 **틱당 24작업, quantum 1**을 유지한다. 후보 검사 또는 셀 방문을 각 1작업으로 세고 무효 작업 폐기도 최소 1작업을 쓴다. 새싹 검색 큐가 성체보다 먼저 처리된다. 새싹 큐는 오래 기다린 검색 하나를 완료한 뒤 다음 검색을 처리해, 모든 새싹이 미완료 커서만 순환하다 결과가 함께 낡는 상황을 줄인다. 새싹은 기존 링/버킷 탐색에서 거리 제한 안의 첫 유효 후보를 찾으면 다음 한 끼 예약을 확정한다. 정확한 최근접임을 증명하려고 나머지 후보를 전부 검사하지 않는다. 성체 큐와 성체 최근접 탐색은 기존 방식을 유지한다. 새싹도 매 SDK quantum마다 예산을 차감한다. 빈 검색은 기존 인덱스/해제 revision 또는 이동량으로 재시도한다.

추가 작업은 위 24작업에 포함하지 않는다. `foodProtection`은 병력과 먹이의 선형 순회로 보호 준비, `foodPickup`은 먹이 주변의 국소 병력 후보, `foodDelivery`는 배달 대상 선택·먹이 생성·배정의 CPU다. 전체 생산 루프는 `foodProduction`으로 따로 본다. `foodProtectionVisits`, `foodPickupQueries`, `foodPickupChecks`, `foodDeliveryVisits`를 별도 계수한다. 전체 정렬이나 병력마다 전체 먹이를 훑는 탐색은 추가하지 않는다. 더미 배정은 기존 일꾼 refresh 주기/변경 시에 실행한다. 기능 E2E 통과는 CPU 성능 또는 실제 PC FPS 보증이 아니다.

## 내부 rollback과 디스크 저장

`foodRuntime`은 내부 체크포인트 전용이다. 양방향 예약(비행/도착 대기 포함), 보호 풀의 순서, 예약 시간·진행 거리, 검색 큐·중간 커서·과거/현재 공간 스냅샷·인덱스 revision을 저장한다. 소비 슬롯은 `null` tombstone을 보존한다. 보호 풀 중복/범위 오류·예약과의 중복도 거절한다. 이전 체크포인트에서 보호 풀이 없으면 빈 풀로 읽고 다음 논리 틱에 현재 정책으로 재구성한다. 이전 `foodRuntime: null` 이행도 유지한다.

일반 디스크 저장 SSOT인 `farm-progress.js`의 계약은 유지한다. 주민/새싹 식사 진행·대기와 먹이 수를 저장하며 재접속 시 실시간 위치·예약·검색·배달 목적지·더미는 복원하지 않는다. 내부 rollback과 재접속의 계약을 구분한다.

## 재현 명령과 회귀

```sh
npm run test:food-reservations
node tests/food-reservations.e2e.mjs --bench
```

첫 명령은 실제 Garden과 로컬 pinned SDK를 Chromium에서 실행하며 renderer/RAF 없이 예약·실제 식사·3회 성장·사망/합성/씬 해제·정체/원거리·디스크 복원·중간 커서 rollback을 검사한다. 220명 검색 중 복원한 전체 상태를 180틱 비교하고 잘못된 체크포인트 거절도 검사한다. core CI에는 이 기능 검사만 추가하며 벤치는 넣지 않는다.

현재 비교 벤치는 기준 `9353f0360735334239d84409e44a2b8f964d6a10`의 전체 모델 모듈을 Git 객체에서 별도 URL로 읽어 후보 전체 모델과 비교한다. 단일 owner만 교체하지 않는다. 같은 초기 병력·위치·식사 상태를 assert하고, 커밋·후보 소스 SHA-256·Chromium/Playwright/Node 버전과 원시 결과를 `tests/output/food-reservations/benchmark-1000.json`에 기록한다. 이 원시 관찰물은 커밋하지 않는다.

seed 424242, dt 0.05, 성체 900+새싹 100, 정원 1,000, 창고 50을 사용한다. 배부름/배고픔/밀집은 400틱, 지속 공급/자동 생산은 3,600틱이다. CPU는 첫 40틱을 제외한 모델 1틱 평균이며 렌더·상태 관찰용 이동량 집계를 제외한다. 추가 보호/근접/배달 메서드 CPU와 방문 수는 24작업과 별도로 기록한다. 측정 wrapper의 비용은 후보 CPU에 포함된다.

지속 공급은 초당 10번 같은 좌표로 수동 비행 먹이 생성 시도를 넣는다. 자동 생산은 노동 배분 20%와 실제 `advanceWork`를 사용하며 수동 먹이를 넣지 않는다. 창고 상한 때문에 시도 수와 실제 생성 수가 다르다. 공급·식사·이동량, 30초 상태, 새싹 성장 평균/마지막 완료와 식사 준비 후 최대 대기를 기록한다. 두 공급 장면에서 100마리 전원 성장 및 평균/마지막 완료·최대 대기의 기준 대비 비악화를 assert한다. 기능 기본 실행과 부하 벤치는 별도 명령이며 CPU 성능과 실제 GPU FPS는 구분한다.

## 이전 예약 구현의 관측 결과와 한계

아래 기록은 이번 근접 섭취·자동 배달 변경의 검증 결과가 아니다. 이번 변경의 동일 조건 기능/CPU 비교와 공개 확인은 해당 PR에 기록한다.

원시 자료는 `docs/benchmarks/food-reservations-fixed-180.json`과 `food-reservations-original-90.json`에 보존한다. 최초 90초 전원 식사 기준은 후보와 기준 모두 달성하지 못했다. 이 실패를 삭제하거나 통과로 바꾸지 않았고, 같은 공급 시도와 시작 조건을 180초까지 관측해 이 fixture에서 기아가 해소되는지를 별도로 확인했다.

과거 220명 비교는 `0233b71335eacbaae2a0921ae758d40a40c4bc5f` 탐색 owner를 교체한 비교였으며 현재 전체 모델 비교와 구분한다.

최초 실패 JSON의 `HEAD`는 당시 `765eb219bce148d2e89cbda6e1667cecb0e434ad`다. 이 기준과 최종 고정 커밋의 먹이 탐색 파일 SHA-256은 모두 `5b46010b7f231595ba8d8ee59e2ebe280326a564281f1017e15de7976be3c257`로 같다. 과거 원시 기록은 그대로 두고, 과거 표는 당시 immutable 커밋의 기록이다.

| 180초 고정 관측                    | 기존 일반 | 예약 일반 | 기존 부족 | 예약 부족 |
| ---------------------------------- | --------: | --------: | --------: | --------: |
| 새싹 20명 마지막 성장(초)          |    122.25 |     23.60 |    149.75 |     37.40 |
| 원래 성체 200명 마지막 첫 식사(초) |    117.90 |    120.35 |    140.40 |    149.20 |
| 총소비                             |       280 |       280 |       280 |       280 |
| 후보 검사                          |    14,749 |    14,841 |    18,442 |    21,349 |
| 셀 방문                            |    38,397 |    38,649 |    38,387 |    39,652 |
| 합계 검색 작업                     |    53,146 |    53,490 |    56,829 |    66,581 |

일반 공급 시도 1,800회, 부족 공급 시도 360회이며 모두 실제 330개 생성·280개 소비·50개 잔여다. 280개는 원래 성체 200식사+새싹 성장 60식사+성장한 20명의 첫 성체 식사다. **총처리량은 모두 초당 1.56개로 같으며 증가하지 않았다.** 새싹 성장 완료는 빨라졌고 성체 마지막 식사는 일반 2.45초·부족 8.8초 늦었다. 검색 작업은 일반 약 0.65%, 부족 약 17.2% 증가했다.

90초 일반 관측에서는 원래 성체 식사가 133→102명, 성장 식사가 29→60회, 성장한 주민 식사가 2→16회였다. 추가 성장 식사는 31회로, 기준도 이미 먹은 부분 진행을 제외하면 54회가 아니다. 총소비는 164→178회이고 창고 여유에 따른 실제 생성도 214→228개였다. 부족 공급은 원래 성체 151→80명, 성장 식사 19→60회, 성장 후 식사 0→9회, 총소비 170→149회였다. 부족 공급에서의 초반 손실을 단순한 분배 차이나 탐색 성능 향상으로 표현하지 않는다.

180초 결과는 이 조건에서 원래 성체와 새싹 모두 완료했다는 근거이며, 임의 맵/무한 공급 경쟁에서 영구 기아가 없다는 수학적 증명은 아니다. 총공급·예산·속도를 늘려 기준을 맞추지 않았다.
