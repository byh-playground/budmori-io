# 병종별 성장 전환 계약

현재 제품은 0.32.0, 싱글 전용이다. **옥수수와 콩의 새 트리가 활성화되어 있다**.
`features/species-growth/definition.js`가 종별 출시 상태를 소유한다. 플레이어 schema 4에서 옥수수와 콩은
`treeVersion: 1`과 `nodeRanks`를 사용하고 다른 7종은 기존 `powerLevel`·`branchLevels`·숙련·효과를 유지한다.
9종 순차 전환이 끝나면 구 투자 실행 경로를 제거하되 실제 0.30 농장 세이브의 단방향 importer는 유지한다.

## 새 트리의 단일 계약

`SpeciesGrowth`는 활성화된 병종의 투자·해금·이관 규칙을 소유한다. DOM·저장소·전투 연출과 독립적이다.

- Lv1에서 1P, Lv50에서 50P. XP는 기존 100 × 1.2^(L−1) 곡선을 사용한다.
- 진화 T2–T6은 각각 2P, 선행 진화를 연구해야 한다. 숙련 해금은 Lv2/6/12/20/30이다.
- 기본 3축은 10랭크 × 1P, 랭크 해금은 Lv1/6/11/16/21/26/31/36/41/46이다.
- 특화 3축은 5랭크 × 2P, 랭크 해금은 Lv11/19/27/35/43이다.
- 전체 용량은 10+30+30=70P. 잔여 포인트는 레벨 예산에서 실제 랭크별 비용을 차감한다.
- 기본·특화 축은 진화 선수조건이 아니다. 합성은 연구와 무관하게 가능하며, 미리 연구해도
  실제 공격은 현재 유닛 등급 이하의 가장 높은 연구 단계만 사용한다.
- 농장에서만 구매·무료 재분배한다. 전투 또는 진행 중인 런에서는 막고 런 시작의 투자를 유지한다.
- 미구현 병종·노드는 구매할 수 없다. 미출시 종의 새 기본/특화 슬롯은 UI에 노출하지 않는다.

## 종별 출시와 저장 경계

0단계는 소비자와 분리된 준비 모델이었다. 옥수수 단계는 실제 소비자를 연결하므로 저장·동작 변경에
맞춰 MINOR를 0.31로 올렸다. 0.30/schema 3 정상 저장만 검증 후 이관하며 원본 raw와 옥수수의
`legacyInvestment`를 보존한다. 나머지 8종은 변경하지 않는다. 미지 스키마나 파싱 실패는 저장 잠금과
내보내기로 이어지며 새 농장으로 자동 초기화하지 않는다.

종별 활성화 PR에는 반드시 다음을 함께 포함한다.

1. 실제 T1–T6 공격·성장축 효과·UI, 종별 availability, 기존 대표 능력의 기본 T1 보존.
2. 플레이어 schema dispatch와 종별 build 교체. 검증된 기존 저장만 `migrateBuild`에 전달하고
   종전 power/branch 투자는 전부 지운다. 별도 환급 보너스를 더하지 않는다. 총 예산이 레벨에서
   파생되므로 시작 1P나 환급이 재접속 때 중복 지급되지 않는다.
3. `farm-progress`의 exact keys 및 깊은 복사, `farm-save-codec`의 이관 경계,
   `farm-snapshot`의 별도 shape/schema, `player-progression`의 영수증 중복 방지를 함께 전환한다.
   기반 모델의 `awardXp`는 영수증 소유자가 아니며 이 함수를 보상 처리기로 직접 호출하지 않는다.
4. 새로 켜진 종만 이관하며 미구현 종은 기존 투자·XP·UI를 유지한다. 런 도중 이관하지 않는다.
   저장 가져오기는 실제 농장 재개 경계에서 적용하고 실행 중인 런의 투자 스냅샷은 유지한다.
5. 새 50레벨에서 남는 XP도 저장한다. 옛 Lv50 초과 저장은 원래 레벨·남은 XP를
   `legacyMastery`에 그대로 보존하고 새 masteryLevel=50, masteryXp=0에서 이후 XP를 따로 누적한다.
   거대한 기하급수 합으로 재계산해 정밀도를 잃거나 XP를 버리지 않는다. 아카이브는 소비/보상이 아니다.
   새 XP는 유한한 0 이상 1e13 미만 값만 받는다. 덧셈에서 보상이 소실되거나 허용 부동소수점
   오차(누적값 크기의 2 epsilon과 보상량의 1e-9 중 작은 값)를 넘으면 원본 불변 실패로 반환하고 영수증도 정산하면 안 된다.
6. 활성종의 저장→재로드→반복 이관, 위조/초과 투자 거부, 늦은 중복 보상, 무료 초기화,
   모바일 투자 UI, 런 종료/복귀까지 검증한다. 9종 전환 후 구 투자 실행 경로는 제거하되
   실제 사용자 구 저장을 읽는 단방향 마이그레이션은 유지한다.

## 공격 action 계약

`AttackAction`은 하나의 평타에 유한 슬롯(최대 32개), 단조 시뮬레이션 tick, 총합 1의 피해 가중치를 둔다.
발동/확률/RAW 소비 예산은 action당 한 번만 claim하고, 슬롯별 같은 대상 ID는 한 번만 맞힌다.
같은 보스의 충돌체 여러 개를 서로 다른 대상 ID로 바꾸면 안 된다. 후속 슬롯은 독립 정상 타격이다.

사망·기절·전투 종료의 소유자는 `cancel()`을 호출한다. 이미 발사한 투사체의 생명주기는 별개이며
각 병종 구현에서 유지/취소를 확정한다. 예를 들어 옥수수 발사체가 취소된 근접 action의 hit ledger에
의존하면 안 된다. 이 모델은 목표 재탐색·RNG·VFX를 만들지 않는다. 렌더 LOD가 실제 슬롯을 줄이지 않는다.

## 검증과 근거

개발 중 임시 모델 검사는 저장소 밖에서 실행하고 결과를 PR에 기록한다. 기존 E2E는 사용자 흐름을
그대로 검증한다. 비활성 상태의 기존 출력·전체 저장 roundtrip 일치와 활성 fixture의 비용/이관 검증을
분리하며, 활성 fixture 통과를 실제 공격·화면·저장 consumer 출시 완료라고 부르지 않는다.

기존 코드와 [Bloom 개발 규칙](https://github.com/byh-playground/bloom-reference/blob/main/rules/development.html),
[관리 규칙](https://github.com/byh-playground/bloom-reference/blob/main/rules/project-management.html)을 기준으로 했다.
[MDN Number.MAX_SAFE_INTEGER](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER)의
정수 정밀도 한계와 [structuredClone](https://developer.mozilla.org/en-US/docs/Web/API/Window/structuredClone)의
깊은 복사를 확인해 tick/rank 검증과 원본 불변 이관에 사용했다. 기술 자료가 게임의 비용·성장 곡선을 정한 것은 아니다.

### 합성 예산과 검증 방법

고정 초기 M=1.75^(g−1)는 flat ATK 카드가 있을 때 재료 집단 대비 하락했다. 예컨대 flat+10/공격+30%
조건에서 실제 120초 전이비는 .925/.932/.754/.749/.849였다. `cornMergeBudgetMultiplier` 한 곳에서
동일 런 T1 ATK / 실제 등급 ATK × 누적 재료 수 × 1.05^(g−1)로 정규화한다. flat0에서는 초기 M과
동일하고 T1은 항상1이다. 공통 permanentStatMultiplier와 giant/passive는 A의 source 계수로 한 번씩
적용하고 M에는 중복 반영하지 않는다. 정규화와 예산은 action 시작에 확정한다. 실제 카드는 비음수이며,
진단용 0/음수/비유한 ATK는 나누지 않고 유한 기본 M으로 기존 0피해 동작을 유지한다. 이 조건에서
DPS 비율을 보장하지 않는다. 임의의 개별 tier override는 제품 카드 조건이 아니다.

비확률 기대값은 +5%와 하한1.00을 확인한다. 확률 조건은 같은20 seed로 합성 전후를 비교한 평균,
표준오차, 95% 신뢰구간, 최저를 모두 기록하고 평균95% CI 하한1.00을 확인한다. 개별 seed의 최저에
맞춰 평균 예산을 올리지 않는다. 10초 예열 후120초를 측정하며 구간 끝의 미완료 부착을 기록한다.
최종 실제 수치·브라우저·성능 결과는 해당 PR의 검증 기록에 둔다. 이 옥수수 보정을 다른 종에 자동 적용하지 않는다.

## 콩 0.32 전환

0.31/schema4의 옥수수 새 투자와 콩 구 투자를 함께 읽고 콩만 전환한다. 0.30/schema3에서는 옥수수와 콩을 함께 전환한다. 이미 새 트리인 투자·XP·아카이브는 그대로 유지하며 알 수 없는 treeVersion은 거부한다. 실제 변경이 있을 때만 원본 raw를 백업하고 검증 저장한다. 동일 저장을 재로드해도 백업을 반복 회전하거나 다시 환급하지 않는다.

기본 T1의 준비0.28초·후딜0.65초와 기존 런 공속의 후딜 단축 방식을 유지한다. 실제20Hz 중립 보스 접근에서 준비 간격은22틱이다. T1부터T6의 타격 비중은[1], [1], [.45,.55], [1], [.4,.6], [.2,.25,.55]이며 첫 접촉 후 슬롯 시점은 각각[0], [0], [0,4], [0], [0,6], [0,3,8]틱이다. T6은 빠른 두 접촉 뒤 더 긴 압축 마무리를 한다. 접촉은 대상 앞면에서 멈추며 자체 반동은 적 넉백이 아니다.

콩은 실제 합성 재료 수와 같은 런의 flat ATK를 보존하는 별도 예산을 사용한다. g=실제등급, f=연구공격형태, Cg=누적재료수, a1/ag=동일 런 T1/실제등급 공격력일 때 M=(a1/ag)×Cg×1.05^(g−1)×(C+추가틱[f])/C이다. C=9+ceil(20×현재후딜), 추가틱=[0,0,4,0,6,8]이다. 후딜의 틱 계산은 부동소수 경계만 보정한다. 영구 공격력·거대화·패시브 배율은 따로 한 번만 반영한다. 이 공식은 콩의 실제 고정 보스 주기 기준이며 이동 표적에게 모든 슬롯의 명중을 보장하지 않는다. 0공격력 진단에서는 유한 참고계수로 처리하고 0DPS 비율은 보장하지 않는다.

재돌진 토큰은 적 강제 이동 종료 뒤60틱(경계 포함) 동안 유효하며 첫 action 시작 시 소비한다. 명중 전 취소·빗나감에도 반환하지 않는다. 전체 직접예산 D는 모든 박치기 +3%/rank와 재돌진 +5%/rank를 먼저 반영하고, 첫·마지막 특화는 각각 D×8%/rank를 해당 슬롯에 가산한다. 단타의 두 보너스는 합산한다. 후딜축은 -1.5%/rank, 회복 기동 특화는2초 이속보너스25%+6%/rank다.
