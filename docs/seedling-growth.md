# 새싹 성장과 획득 표현

먹이 0·1·2회에는 같은 새싹 아트를 0.32·0.56·0.80 배율로 표시한다. 세 번째 식사는 기존 모델 규칙대로 성체로 전환한다. 크기·접촉 반경·높이는 `unit-body/definition.js`의 같은 식사 기반 정의를 사용하며, 시간이 흐르거나 오프라인 시간이 생겼다는 이유로 커지지 않는다. 성장 중 모델의 `seedling`과 완성된 species 9 병사는 별개다.

## 새싹은 병종이 없다

성장 중 새싹은 어떤 병종도 아니다. `unit.species`는 `null`이고, 자라서 될 병종은 `seedling.heritage`에만 있다. `heritage`는 성장 전환(`feedSeedling`)과 저장(`savedSpecies`)만 읽는다. 세 번째 식사에서 `Unit.setSeedling(null)`이 `heritage`를 `species`로 넘겨주고, 이 순간 병종이 확정된다. 농장은 그때 `unitCollection.refreshIndexes()`로 그 병종의 집계·묶음에 유닛을 다시 올린다.

- 번식 몫·출전 순서·병종 집계·종별 묶음은 `species`가 있는 유닛만 센다. 새싹은 `speciesCounts`·`ownedCounts`에서 빠져 어떤 병종 칩도 만들지 않는다.
- 보상 대기(공간이 없어 못 놓은 씨앗)는 병종 그림 없이 새싹 하나의 숫자로 보인다. 보상 창의 "첫 격파!" 표시도 병종을 알려 주지 않는다.
- 전투 투입은 출전 순서의 병종이 모두 끝난 뒤 새싹이 마지막에 들어간다(`deployOrder` 뒤의 `null`).
- 저장 형식(`species`와 `seedling: { fed, cooldown }`)은 그대로다. 새싹 행의 `species`는 `heritage`를 담는다. 내부 체크포인트 스냅샷은 `species: null`과 `seedling.heritage`를 가진다.
- 병종 소유 판정(`bossSpeciesOwned`, 보상의 "씨앗 한 쌍" 규칙)은 성체만 센다. 새싹만 있는 병종은 아직 없는 병종으로 본다.

## 성장 중에는 순수 새싹으로 싸운다

성장 중 새싹은 그림만 새싹인 최종 병종이 아니라 능력 없는 순수 새싹(species 9)이다. `species-catalog.js`의 `kitSpecies(unit)`가 그림·몸·기본 공격·능력·스탯을 고르는 유일한 기준이고, 성장 중이면 9, 아니면 `unit.species`를 돌려준다. `unit.species`는 계통·도감·성체가 될 병종으로만 남는다. 전투 판정에서 `unit.species`를 직접 읽지 않고 `kitSpecies`를 쓴다.

`Unit.setSeedling(state)`가 성장 단계의 유일한 변경 지점이다. 새싹이 되거나 성체가 되면 공격·능력 모음을 다시 만들고, 현재 체력은 새 최대 체력에 대한 비율을 유지한다. 세 번째 식사로 성체가 되는 순간 그 병종의 스탯과 능력이 켜진다.

`features/seedling-growth/definition.js`가 1.15초 표현 시간과 0.4초 정점·1.35 높이의 상승/착지 곡선을 소유한다. 실제 모델은 즉시 성장을 확정하고 계속 이동한다. 모델 z를 바꾸거나 기다리게 하지 않는다. 표현 DTO와 단일 display proxy가 정점까지 이전 새싹 외형을 유지하고, 정점에서 병종 외형으로 바뀐 뒤 착지한다. 기존 merge 반짝임을 재사용하며 효과가 따라가는 위치는 같은 proxy에서 읽는다. 그림자는 기존 바닥 경로를 사용한다.

최신 코드 얼굴·눈/입 소켓·neutral 몸 atlas는 유지한다. sprite/vector 모두 최종 display proxy의 몸 행렬로 같은 얼굴 레이어를 그린다. 새싹의 식후 표정은 `seedling.fed`를 읽지만, 모델 `fed`는 기존 성체 식사·번식 계약 그대로다.

성장 확정 시 codex가 해당 병종을 처음 발견했는지 모델에서 판단한다. 카드 owner `SeedlingReveal`은 committed notice만 받고 병종별 중복을 제거하며, 착지 뒤 4.5초간 표시한다. 카드는 게임을 멈추지 않으며 메뉴/도감에 가려지면 기다린다. 기존 병종 성장에는 카드가 없고 효과만 있다. 모델 효과 메타데이터는 기존 내부 snapshot에 보존되지만 일반 저장은 진행만 저장하므로 재접속 시 획득 연출을 재생하지 않는다. 오프라인 복원에서 과거 소유자를 검색해 카드를 만들지 않는다.

## 직접 검증

`npm run test:seedling-growth`는 실제 식사 0→1→2→3과 물리 크기 증가, 양쪽 렌더 제출, 상승/정점/착지·actor 하나, 최초 카드 대기·500회 기존 성장 카드 없음·서로 다른 병종 큐·모바일 표시·저장/재접속/오프라인을 검사한다. 실제 얼굴 제출 행렬과 눈/입 소켓 좌표 일치, 그리기 전후 모델 높이/z 불변, 내부 효과·먹이 runtime 복원과 성장 식사 예약 해제도 확인한다. 먹이 예약 타깃 테스트를 함께 실행해 PR406 계약을 유지한다. 전체 게임 회귀는 이 기능의 완료 게이트로 추가하지 않는다.
