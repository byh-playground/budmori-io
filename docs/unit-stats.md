# Common unit stats

이 문서는 공통 유닛 스탯과 종별 공격 프로필의 기준을 설명합니다. 전투 수치의 단일 원본은 `src/unit-stats.js`와 `src/unit-abilities.js`입니다. 현재 종별 공통 스탯은 모두 중립 기본값이며, 새 시스템을 추가한 것만으로 기존 밸런스가 바뀌지 않습니다.

## 공통 스탯

| 스탯 | 기본값 | 적용 |
| --- | ---: | --- |
| `maxHp` | 티어 공식 | 현재 HP 상한과 UI 체력 총량 |
| `attackPower` | 티어 공식 | 종별 `skillMultiplier`를 곱한 기본 공격력 |
| `armor` | 0 | `100 / (100 + 유효 방어력)`로 받는 피해 감소 |
| `armorPenetration` | 0 | 대상 방어력에서 비율만큼 차감, 0–1 범위 |
| `moveSpeed` | 1 | 기존 농장 이동 속도와 레이드 접근 속도 배율 |
| `attackSpeed` | 1 | 종별 회복 시간의 역수 배율. 공격 예고 `windup`은 유지 |
| `critChance` | 0 | 공격 1회당 치명타 확률, 0–1 범위 |
| `critMultiplier` | 2 | 치명타 시 방어 계산 전 피해 배율 |
| `attackArea` | 1 | 근접 스윕 반경과 투사체 충돌 반경 배율 |
| `lifesteal` | 0 | 일반 직접 공격의 실제 HP 손실을 바탕으로 한 회복 비율 |
| `regen` | 0 HP/s | 살아 있는 유닛의 초당 회복량 |
| `healingReceivedMultiplier` | 1 | 흡혈과 재생을 포함한 회복량 배율 |
| `knockbackPower` | 1 | 주는 넉백의 힘 배율 |
| `knockbackResistance` | 0 | 받는 넉백 힘에서 차감하는 비율, 0–1 범위 |
| `statusDuration` | 1 | 주는 제어 효과 지속시간 배율 |
| `statusResistance` | 0 | 받는 제어 효과 지속시간에서 차감하는 비율, 0–1 범위 |

기본 스탯은 동결된 종별 프로필·등급 정의만 캐시하며, 전투의 읽기 전용 경로가 재사용합니다. `resolveUnitStats()`와 `farm-model`의 공개 `stats()`는 매번 독립된 수정 가능한 결과를 반환합니다. 유닛의 종·등급 변경은 다음 호출에 반영하고, 시간에 따라 바뀌는 버프·오라·대상 방어력·외부 override는 캐시하지 않습니다. 전투 대상 ID와 밀 오라 후보는 기존 유닛 인덱스를 재사용하며 생성·제거·복원 또는 외부 상태 변경 후 다시 동기화합니다.

등급 기본 스탯은 등급 전이의 재료 비용에서 파생합니다. 다음 등급 재료 비용이 `cost`일 때 `maxHp *= 1.5 × cost/2`, `attackPower *= 1.2 × cost/2`를 적용합니다. `src/unit-grades.js`가 등급과 재료 비용의 단일 기준이며, 스킬은 여기에 종별 `skillMultiplier`를 곱합니다.

| Tier | Grade | 이전 등급 재료 수 | HP | ATK |
| ---: | --- | ---: | ---: | ---: |
| T1 | Common | — | 40 | 4 |
| T2 | Uncommon | 2 | 60 | 4.8 |
| T3 | Rare | 2 | 90 | 5.76 |
| T4 | Epic | 3 | 202.5 | 10.368 |
| T5 | Legendary | 4 | 607.5 | 24.8832 |
| T6 | Mythic | 5 | 2278.125 | 74.6496 |

## 등급과 합체 합의

등급 표기는 `Common → Uncommon → Rare → Epic → Legendary → Mythic` 순서이며 각각 T1–T6에 대응합니다. 다음 등급을 만들 때 필요한 재료는 T1→T2 2마리, T2→T3 2마리, T3→T4 3마리, T4→T5 4마리, T5→T6 5마리입니다. 재료는 모두 같은 종·같은 등급이어야 하고, 살아 있는 성체이며, 쿨다운·전투 중이 아니어야 합니다.

한 번에 합체 그룹 하나만 처리합니다. 합체 가능한 그룹은 낮은 등급부터 선택하고, 그 등급에서는 가장 가까운 적격 재료를 묶습니다. 합체 뒤 종별 보유 수는 정확히 `existingCount - materialCount + 1`로 계산해 2 이상이어야 합니다. 따라서 T2/T3 합체의 최소 기존 수는 3마리, T4 합체는 4마리, T5 합체는 5마리, T6 합체는 6마리입니다. 사망·수면 병력은 재료가 될 수 없지만 보유 수 계산에는 포함됩니다. 합체 애니메이션은 각 재료가 결과 위치로 순차 이동하는 것으로 표시합니다.

기존 크기 성장, 이동 속도, 사거리 곡선은 유지합니다. 저장·네트워크 검증과 레이드 출전/정산은 T1–T6을 허용하며, 레거시 저장의 일회성 2재료 합체 작업은 안전하게 취소됩니다.

## 종별 공격 프로필

공통 스탯은 모든 종에 적용되고, `src/unit-abilities.js`는 종별 행동만 정의합니다. 각 프로필은 `kind`, `windup`, `recovery`, `range`, `skillMultiplier`, `projectileCount`, `bounces`를 가집니다. `range`는 현재 AI가 유지하는 보스와의 선호 간격이며 기존 간격을 보존합니다.

| 종 | 공격 유형 | 선호 간격 | 예고 | 회복 | 스킬 배율 | 투사체/도약 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 완두 | 돌진 | 1.45 | 0.28s | 0.65s | 1.0× | 없음 |
| 옥수수 | 포물선 투사체 | 4.1 | 0.38s | 1.25s | 1.6× | 투사체 1개 |
| 팥 (레거시 종 ID: `kidney-bean`) | 도약 | 2.5 | 0.32s | 0.9s | 1.3× | 도약 |

## 새 병종 설계·추가 체크리스트

새 병종을 추가할 때는 외형 하나나 공격 동작 하나만 구현하지 않고, 정원 성장부터 보스전과 저장까지 전체 흐름을 함께 설계한다. 각 병종 변경은 아래 항목을 기획·구현·검증하고 PR에서 확인할 수 있게 한다.

1. **역할과 읽기 쉬운 표현**: 병종의 전투 역할과 구분되는 실루엣을 정한다. 기본 대기·이동·공격, 공격 예고와 접촉, 피격·쓰러짐·회복에 필요한 애니메이션과 효과를 연결하고 시각 요소만으로 상태를 오해하지 않게 한다.
2. **기본 공격과 스탯**: 병종별 기본 공격 프로필(`kind`, `windup`, `recovery`, `range`, `skillMultiplier` 등)과 공통 스탯을 명시한다. 피해를 주는 기본 공격·특수능력은 티어 기본 `attackPower`의 배율을 밝히고, 이 문서의 피해 처리 순서와 방어·치명타·회복 규칙을 따른다. 다른 효과도 대상·발동 조건·지속시간·재사용 간격 또는 제한·중첩·수치 산식을 구현 전에 정의한다.
3. **성장과 해금**: 공용 스탯 트리와 병종 전용 능력 트리를 구분한다. 공용 스탯과 모든 능력 트리는 같은 종류의 공용 포인트를 사용하고, 먹이는 정원 성장에만 쓴다. 콘셉트에 맞으면 한 병종에 복수의 특수능력을 둘 수 있고 플레이어는 각 능력을 독립적으로 선택한다. 각 능력은 별도 root와 별도 트리를 가지며, 병종당 하나의 root로 여러 능력을 묶지 않는다. 각 능력의 root 해금은 Rare 등급 이상을 요구하고, 그 root 뒤에 능력 강화와 적용 최소 등급 완화 두 branch를 둔다. 등급 완화는 최소 적용 등급을 Uncommon에서 Common까지 낮춘다. 능력 희귀도와 적용 대상 유닛의 최소 등급은 별개다. 모든 노드는 공용 포인트 1개로 투자하며, 해당 능력의 두 branch 모두에 투자할 수 있다. 따라서 같은 병종의 여러 능력 트리에 각각 투자할 수 있다. 후속 강화는 최소 적용 등급을 낮추거나 공격·행동·효과 표현의 알아보기 쉬운 시각적 구조 차이를 만드는 방향을 중심으로 검토하며, 외형만의 변화로 한정하지 않는다. 피해 능력은 티어 기본 `attackPower` 배율을 밝히고, 새로 필요한 미지정 수치는 단위와 규모에 맞춰 적절히 정규화하고, 연관 값은 가능한 한 하나의 명시적 기준값에서 파생한다. 예시 배율은 설명용이며 보편 기본값이 아니다. 사용자가 지정했거나 이미 합의·구현된 값은 별도 요청 없이 재정규화하지 않는다 ([Bloom Reference 수치 초안 원칙](https://github.com/byh-playground/bloom-reference/blob/main/rules/ai-development.html#numeric-drafts)). 수치 변경은 별도 근거와 검증을 둔다.
4. **보스화와 보스전 상호작용**: 병종 기본 스탯과 특수능력의 기여분을 분리해 평가한다. 병종을 보스로 사용할 때는 T1 기준 스탯 배율, 크기·접촉 판정, 공통 보스 패턴의 적용 방식과 조합을 명시한다. 아군 병력으로 사용할 때는 실제 보스의 스탯과 공통 패턴 조합에서 사거리, 발동 시점, 명중 대상, 방어·제어 효과 및 전사 조건을 확인한다. 다수 병력과 반복 발동에서도 패턴 회피, 무한 발동, 과도한 피해나 생존 이득이 생기지 않는지 검증한다.
5. **획득·정원 생애주기**: 획득, 번식, 성장, 합성, 출전, 전투 복귀, 저장·불러오기 경로를 확인한다. 모든 병종은 공용 `Common` T1–`Mythic` T6 등급 카탈로그, 재료 비용, HP/ATK 전이 공식과 합체 최소 보유 수 규칙을 따른다. 병종별 능력은 별도로 최소 적용 등급을 정의할 수 있지만 전역 등급 상한과 비용을 바꾸지 않는다. 새 병종의 저장 데이터가 필요한 경우 현재 세이브 호환·가져오기·검증 규칙과 명시적으로 대조하고, 미지원 저장을 조용히 변환하거나 덮어쓰지 않는다.
6. **싱글·온라인 동일성**: 새 행동과 상태는 기존 결정론적 `Garden` 시뮬레이션 안에서 처리한다. 난수는 시뮬레이션 seed 흐름을 따르고, 동일 입력이 싱글과 멀티플레이에서 같은 전투 결과를 내는지 검증한다. 표현 전용 효과는 권위 시뮬레이션 상태와 분리한다.
7. **검증 증거**: 병종 스탯·공격·특수능력 단위 테스트, 보스 패턴과의 실제 접촉/상태 전이 검증, 정원 저장·복귀 및 싱글/온라인 동등성 테스트를 PR에 제시한다. 애니메이션·보스 상호작용은 정적 수치만 보지 말고 제품 경로에서 확인한다.

### 합의된 기획 방향과 미정 세부 사항

아래에는 여섯 특수능력의 합의된 기획과 아직 확정되지 않은 수치·조합·운영 규칙을 구분해 기록한다. 등급 및 합체 규칙은 위의 현재 구현 계약을 따른다. 능력·전투 세부 사항의 코드 구현 상태는 관련 PR과 검증 결과에서 별도로 확인한다.

- **등급 표기와 구현 범위**: `Common → Uncommon → Rare → Epic → Legendary → Mythic`는 T1–T6이며 색상은 `src/unit-grades.js`에서 단일 관리한다.
- **현행 성장과 합체**: 재료 비용은 T1→T2 2, T2→T3 2, T3→T4 3, T4→T5 4, T5→T6 5다. 각 합체는 같은 병종·같은 등급의 살아 있는 성체만 사용하며, 한 번에 한 그룹씩 낮은 등급부터 처리한다. 합체 후 같은 종의 보유 수는 `existingCount - materialCount + 1 >= 2`여야 한다. HP·ATK는 재료 비용 비례 전이 배율을 사용하고 표의 값이 기준이다. 확률이나 실패 손실은 없다.
- **성장 포인트**: 공용 스탯과 모든 능력 트리는 하나의 공용 포인트를 사용하고, 먹이는 정원 성장에만 쓴다. 시작 상태는 플레이어 레벨 1, XP 0, 포인트 0이며 시작 포인트는 따로 지급하지 않는다. 보스 처치마다 100 XP를 얻고, 농장 보스전과 레이드 보스전의 보상량은 같다. 레벨 1에서 2까지 필요한 XP는 100이며, 현재 레벨을 `level`이라 할 때 다음 레벨업 필요량은 `100 × 1.2^(level−1)`이다(예: 100, 120, 144...). 레벨이 오를 때마다 공용 포인트 1개를 얻는다. 레벨업에 쓰고 남은 XP와 사용하지 않은 포인트는 각각 이월된다.
- **능력 트리**: 각 특수능력은 독립된 root와 트리를 가지며, 병종 하나의 root에 여러 능력을 묶지 않는다. 각 능력의 root는 Rare 등급 이상에서 해금하고, root 뒤에 해당 능력 강화와 최소 적용 등급 완화(Uncommon → Common)의 branch를 둔다. 능력 희귀도와 유닛 등급은 서로 다른 기준이다. 각 노드는 공용 포인트 1개를 사용하고, 각 능력의 두 branch 모두에 투자할 수 있다. 같은 병종의 여러 능력은 각각 따로 투자할 수 있다.
- **쓰러짐과 복귀**: 일반 유닛은 전투에서 쓰러진 뒤 60초간 수면하고 재사용할 수 있다. 수면 중에는 번식·합성 대상이 아니다. 이는 확정 기획이다.
- **능력 선택과 재분배**: 콘셉트에 맞으면 한 병종에 복수의 특수능력을 둘 수 있으며, 사용자가 공용 포인트를 투자해 선택한다. 포인트 재분배는 무료이고 농장에서만 허용한다. 전투 중 변경은 잠그며 농장 보스전도 전투로 취급한다.
- **밤톨(후속 이벤트 종 3)**: 일반 밤톨 병종은 목표를 향해 부채꼴로 가시를 발사한다. 발사 수는 기본 3발에서 강화 1·2단계에 5발·7발이다. 발당 티어 기본 ATK ×0.5 피해와 기본 공격 전체 주기 ×4의 발사 간격은 밸런스 검증을 위한 초안일 뿐, 확정 규칙이 아니다. 발사 사거리와 이 초안의 최종 채택 여부는 별도로 검증한다.
- **콩 분열**: 콩이 전투에서 사망할 때 같은 종의 T1 콩 2마리를 생성해 해당 전투를 이어간다. 생성 개체에는 별도 수명 제한이 없고 해당 전투가 끝날 때까지 남지만, 영구 보유 병력에 추가되지 않으며 번식·합성 대상이 아니고 다시 분열하지 않는다. 원본은 일반 유닛과 같은 60초 수면·재사용 규칙을 따른다. 능력 강화 경로는 생성 수를 2 → 3 → 4로 두 단계 올리며 각 단계에 공용 포인트 1개를 쓴다. 강화 후에도 생성 개체는 T1이다.
- **팥(기존 도약종; 레거시 종 ID: `kidney-bean`)**: 연속 도약과 착지 충격파는 각각 별도의 Rare+ root, 강화 branch, 최소 적용 등급 완화 branch를 가진 독립 능력 트리다. 연속 도약의 착지 시 도약 재사용 대기시간 초기화 확률은 기본 20%이고, 강화 1·2·3단계에서 35%·50%·65%다. 강화마다 15%p 증가하고 최대는 65%다. 착지 충격파는 각 착지마다 원형 범위로 한 번 발동한다. 충격파 기본·강화 1·강화 2의 피해는 각각 티어 기본 ATK ×1·×1.5·×2, 반경은 기본 공격 사거리 ×1·×1.5·×2다. 두 능력 트리에 모두 투자할 수 있으며, 둘 다 습득하면 연속 도약으로 추가된 착지를 포함해 매 착지마다 충격파가 발동한다. UI에 보이는 충격파 범위와 실제 판정 범위를 일치시킨다. 사용자가 지정한 수치이므로 미지정 수치 정규화 원칙으로 변경하지 않는다.
- **옥수수 병종**: 알갱이 연사(corn-burst)와 팝콘 연쇄 폭발은 각각 독립된 root·트리이며, 각 능력의 강화 branch와 최소 적용 등급 완화 branch에 따로 투자한다. **알갱이 연사**는 발당 티어 기본 ATK ×0.8 피해를 주며, 발사 수는 기본 2발에서 강화 1·2단계마다 3발·4발로 늘어난다. 발사 시점은 기존 기본 공격 한 주기 안에 시간차를 두고 분할하며 별도 0.5초 간격을 고정하지 않는다. 발당 ×0.8은 기존 단발 ×1.6을 절반씩 나눈 값으로, 기본 2발일 때 기존 총 피해를 보존한다. **팝콘 연쇄 폭발**은 알갱이가 착탄한 뒤 1초 후 폭발하며, 다른 팝콘 폭발 범위에 닿으면 즉시 연쇄 폭발한다. 각 알갱이는 한 번만 폭발한다. 폭발 피해는 기본·강화 1·강화 2에서 각각 티어 기본 ATK ×0.5·×1·×1.5다. 기본 폭발 반경은 기본 공격 사거리 ×0.25이고, 반경 강화 1·2단계는 초기 반경의 ×1.5·×2다. 여러 알갱이의 피해는 합산될 수 있지만 같은 알갱이의 한 번의 폭발은 같은 대상을 중복 판정하지 않는다.

밤톨의 확정 기획은 목표를 향한 부채꼴 가시 발사와 발사 수 3→5→7이다. 발당 ATK ×0.5와 기본 공격 전체 주기 ×4의 발사 간격은 검토용 초안으로, 아직 확정되지 않았다. 밤톨의 발사 사거리도 미정이다. 옥수수의 두 능력은 위에 적은 범위의 발사 수, 공격 주기 내 분할, 연쇄 조건, 피해와 반경이 확정 기획이다. 이 문서에 적지 않은 구현 세부 사항은 별도 확정 전까지 미정으로 취급한다. 콩 생성 개체의 제한 없는 전투 한정 수명과 재분열 금지는 확정 사항이며, 팥의 두 능력은 독립 트리이고 동시 보유 시 연속 도약의 매 착지에 충격파가 발동한다. 미정 내용을 확정 규칙으로 취급하지 않으며, 미정 수치와 세부 동작은 기획·밸런스 검토를 거쳐 확정한다. 현재 지원 상한은 T6 Mythic이며 저장·네트워크·레이드 경로도 이 등급을 허용한다.

## 피해와 회복 처리 순서

1. 티어 공격력에 종별 스킬 배율과 현재 공격 버프를 적용합니다.
2. 공격 단위로 치명타를 판정하고, 치명타 배율을 적용합니다. 광역 공격은 한 번의 치명타 판정을 모든 대상에게 공유합니다.
3. 방어 관통을 적용한 뒤 대상 방어력으로 피해를 줄입니다. 보스 방어력은 기존 규칙대로 현재 체력 비율에서 계산됩니다.
4. 남은 체력보다 큰 피해는 실제 체력 손실까지만 계산합니다.
5. 직접 공격 흡혈은 실제 체력 손실 합계로 계산합니다. 광역 공격은 각 대상의 방어 후·과잉 피해 제외 손실을 합산하고, 그 합계의 1/3 비율만 회복합니다. 최종 회복량은 최대 체력을 넘지 않습니다.

상태 지속 피해와 반사 피해는 흡혈을 발생시키지 않습니다. 소환 유닛의 공격은 그 소환 유닛의 자체 스탯으로만 회복하며 소유자에게 이전하지 않습니다. 회복은 `healingReceivedMultiplier`를 거쳐 공통 상한 처리에 들어갑니다.

일반 공격·투사체·착지 충격파·호두 내려찍기·팝콘 폭발은 `Garden.damageCombatTarget`에서 같은 공격 배율·버프·수확·치명타·흡혈 경로를 사용합니다. 공격 컨텍스트는 출처, 단일/광역 여부, 배율, 치명타 난수와 이미 맞힌 대상을 소유하며, 보스와 소환병이 섞인 광역 공격도 컨텍스트 하나를 공유합니다. 대상 방어와 피격 후 표현·넉백·사망 처리는 별도로 유지합니다. 팝콘은 기존의 대상별 난수 소비를 바로잡아 폭발 한 번에 최대 한 번만 치명타 난수를 소비합니다. 대상이 없거나 치명타 확률이 0이면 소비하지 않으며, 대상 처리 순서와 각 대상의 방어 산식은 유지합니다.

## 저장과 네트워크

스탯 프로필은 정적 코드 설정이며 유닛 저장 데이터에 복제하지 않습니다. 기존 세이브의 스냅샷 모양을 바꾸지 않으며, 싱글과 온라인 모두 동일한 `Garden` 결정론 시뮬레이션을 사용합니다. 확률형 치명타가 설정되면 시뮬레이션 시드 PRNG에서 공격 단위로 한 번만 난수를 가져옵니다. 현재 종별 프로필은 모두 중립값이므로 기존 전투의 숫자와 난수 소비 순서는 그대로입니다.

### 주요 코드

- `src/unit-stats.js`: 공통 기본값, 티어 곡선, 피해·회복·제어 계산.
- `src/unit-abilities.js`: 종별 공격 행동 프로필.
- `src/farm-model.js`: 농장/레이드의 공통 시뮬레이션 적용점.

산식과 경계값 단위 검사는 개발 중 검증 수단으로 사용하고 제거했습니다. 유지되는 브라우저 검증은 사용자 흐름을 대상으로 하며 `npm test`로 수동 실행합니다.

## 땅콩·호두 특성 구현 초안

기본 공격 한 사이클 뒤 특성을 연결하는 기존 구현 명세를 적용한다. 아래 값은 구현·밸런스 검증을 위한 **초기 초안값**이며 사용자 확정 수치로 기록하지 않는다. 조정 가능한 단일 수치 원본은 `src/ability-catalog.js`다.

- 땅콩 `분리 협공`: 기본은 한 개체·두 알·2타다. Rare root 해금 시 3타, 강화 시 4타·5타이며 타격당 ATK ×0.5다. 총 공격 시간은 기본과 같은 0.5초, 각 타격은 `(index + 0.5) / count`에 한 번만 판정한다. 궤적은 기본 ±15°에서 ±30°로 넓히며 SVG에 3·4·5타 클립을 둔다. HP·위치·타겟·인구는 여전히 하나다.
- 호두 `웅크리기 반격`: root가 열린 아군만 일반 공격 회복 구간의 마지막 50%에 방어한다. 첫 유효 피격의 피해는 0.75배, 넉백은 0.5배이며 다음 기본 공격 1회를 강화한다. 피격 기절은 그대로 받지만 강화 대기는 기절로 지워지지 않는다. 다음 공격 시작 시 대기를 한 번 소비하며, 그 강화 공격의 회복 구간에는 방어하지 않는다. 사망·수면·전투 종료에는 강화 대기를 지운다.
- 강화 내려찍기의 피해는 ATK ×1.5 → ×1.75 → ×2다. 충격파 반경은 기본 사거리 ×0.5에 ×1 → ×1.25 → ×1.5를 적용한다. 망치와 충격파는 같은 공격 이벤트이며, 기본타와 추가 피해를 중복 적용하지 않는다. 반경 내 적만 대상당 한 번 적중하고 치명타 판정 1회를 공유하며 실제 피해 합계의 흡혈률 ×1/3만 회복한다.
- 두 특성 모두 독립 Rare root, 능력 강화, 최소 등급 T3→T2→T1 완화 경로를 사용하고 각 노드는 공용 XP 포인트 1개다. 보스와 적 소환병에는 플레이어 특성을 적용하지 않는다.
- 구 저장은 두 새 능력 키와 방어 대기·타격 슬롯 필드만 기본값으로 보충한다. 기존 투자·미사용 포인트·플레이어 XP·현재 타격 mask를 보존하고, 알 수 없는 키나 잘못된 투자는 검증에서 거부한다. Raid의 owner별 능력 snapshot도 같은 additive migration을 적용한다.


## 재사용 공격 능력 조합

`unit-abilities.js`의 `UNIT_CAPABILITY_COMPOSITIONS`가 기본 공격과 선택 trait를 배정합니다. 병종 번호는 이 배정에만 사용하고 실행부는 capability의 직접 메서드를 호출합니다. 새 종도 같은 capability를 선택할 수 있으며 현재 배정과 수치는 바꾸지 않습니다.

- 기본 공격: 궤적 접촉, 곡사 발사, 시간 슬롯 연타
- 선택 trait: 연타 강화, 연발, 팝콘, 착지 타격, 착지 충격파, 재도약, 회복 중 방어, 발사 시 부채꼴 탄, 사망 분열, 처형 보정, 적중 시 아군 치명타 강화, 적중 시 방어 감소
- `AttackCycle`은 공통 준비/실행/회복/중단 전환만 관리합니다. `unit-attack-capabilities.js`가 시작 시 한 번 조합한 메서드를 직접 호출하며 프레임마다 component 목록을 순회하지 않습니다.
- 연타 mask·대기 탄·방어 사용 여부·다음 공격 강화·발사 주기·적중 버프는 해당 capability가 갱신합니다. 기존 action/unit 필드 이름과 저장 구조는 그대로 유지하고 `createUnitAttackCycle`로 메서드만 재수화합니다.
- 특수 능력 해금은 계속 소유자의 progression을 조회합니다. 적 진영/거대 보스 소환체에는 progression을 주지 않아 특수 능력 잠금을 유지합니다. 피해·광역 치명타·흡혈은 공통 피해 경계를 사용합니다.
