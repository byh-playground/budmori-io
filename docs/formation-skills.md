# 편성 스킬 · 0.41.3

종별 패시브와 별개의 9종 자동 스킬이며, 탑에서 얻는 한 판짜리 유물입니다. 탑의 유물 문에서 새 유물을 얻거나
이미 가진 유물을 1레벨 올립니다. 한 판에 최대 3종, 유물당 최대 Lv.5(임시 값)이며 런이 끝나면 모두 사라집니다.
영구 습득·슬롯·장착·XP 포인트 소비는 없습니다. 유물은 그 판의 모든 층 전투에 자동으로 적용됩니다.

예약이 아닌 `MODEL.cast` 성공 시 시작합니다. 전투 시작은 게이지 0·쿨 준비 상태입니다.
쿨 중 조건도 누적하며 100%에서 넘는 분량은 버립니다. 발동할 때 0으로 돌아갑니다.

거대화는 이미 적용 중인 아군을 제외하고 1~2명만 남으면 있는 만큼 적용합니다.
HP와 최대 HP는 바꾸지 않으며 종료 후 짧은 크기 출렁임과 함께 오라가 사라집니다.

## 출처와 소유권

Garden의 onCombatResolved Signal이 실제 HP 손실·적중·치명타·쓰러짐을 전달합니다.
FormationSkills가 편성 게이지·효과 수명을 소유하고 UnitCollection이 모든 복사체 추가·제거를 소유합니다.
피해와 적중은 일반 공격 및 기존 병종 능력을 포함합니다. 편성 스킬 피해/회복, 복사체와 그 투사체는
기여하지 않습니다. 거대화 버프로 증가한 피해는 실제 HP 손실에서 배율 비율만큼 분리해
원래 몫만 조건에 넣습니다. 과잉 피해도 실제 HP 손실을 넘겨 충전하지 않습니다.
전투 시간 조건을 위한 공통 집계는 있지만 현재 9종에는 처치·수동 도약·시간 조건을 배정하지 않았습니다.

UnitCollection의 건강 Signal로 부상자 집합을 유지하므로 치유의 비가 매 틱 전체 병력을 스냅샷하지 않습니다.
밀집도·범위 적중·공중 분리는 기존 FixedSpatialGrid를 사용합니다. 원본 저장소와 고정 GameKit에는 별도
공중 soft-separation API가 없어 두 비행 스킬이 동일한 격자 기반 완만한 반발 경로를 공유합니다.
강제로 완전 비겹침을 보장하지 않습니다. 효과의 age·위치는 기존 GameKit presentation 보간으로 표시합니다.

## 복사와 버프 정책

복사체는 현재/최대 HP 1이며 원본의 종·등급·기본 스탯·성장 모습·표정 seed와 해금된 병종 능력을 따릅니다.
거대화·밀 지휘·보리 방어 감소·공격 중 가드 등 임시 상태는 생성 시 복사하지 않습니다.
새 복사체가 나중에 독립적인 거대화 대상이 되는 것은 허용하며 버프는 원래 시각에 만료합니다.
복사체는 밀집도·재복사·모든 편성 조건에서 제외하고 사망 분열도 막습니다. 원본 사망이 복사체를
즉시 지우지는 않습니다. 고정 수명 없이 죽거나 전투가 끝날 때만 제거합니다.

## 병력 스킬의 기존 크기·초기값

- 운석·복사 기본 반경: 원본 SVG 신체 정의의 T1 콩 몸통 지름 3배. 유성우는 1배입니다.
- 운석은 적 중심에서 적 반경 + T1 지름 3배 이내의 면적 균등 무작위 지점을 택합니다.
  낙하 0.75초 전에 지점을 고정하며 후속 명중 보정은 없습니다. 유성우도 각 지점을 독립 고정합니다.
- 큰 운석 넉백은 기존 병력 넉백 5·들림 2를 재사용합니다. 거대 적도 수평 속도 5로 밀리고
  초당 지수 감쇠 6으로 감속하며 경기장 경계를 벗어나지 않습니다.
- 우주선/뇌운은 0.5초 등장 후 공격 시계를 시작하고, 0.5초 동안 떠나거나 흩어집니다.
  추적 속도 6, 공격/재탐색 거리 18, 공중 분리 거리 1.4입니다.
  우주선은 실제 아래 투영 지점의 적 한 명만 공격하고 빔 반경은 0.12입니다. 목표가 옆으로 빠지면 빗나갑니다.
  뇌운은 사거리 안의 목표에 곡선 아크로 타격합니다. 사망 시 재탐색하며 사거리 밖에서도 수명은 갑니다.
- 각 발동이 별도 개체를 추가합니다.
- 복사체 폭증 방지는 기존 장면별 전투 개체 예산에 임시 여유 2,000개를 더한 상한입니다.
  선택한 원본을 전부 복사할 여유가 없으면 부분 복사하지 않고 발동을 보류합니다.
- 치유는 실제 회복 총량을 고정하므로 일반 회복 배율로 총량을 추가 증폭하지 않습니다.
  틱의 남는 회복은 같은 틱의 다른 부상자에게 재분배하며 부상자가 없으면 그 시간 몫은 소멸합니다.

## 저장과 검증

유물은 한 판 안에서만 유효해 디스크에 저장하지 않습니다. 새로고침하면 그 판은 사라집니다.
전투 개체·복사체·게이지·버프·비행 개체 스냅샷도 디스크에 저장하지 않습니다.
내부 결정론 checkpoint만 별도 formationRuntime과 임시 Unit 필드를 보존합니다.

기본 PR 검증은 `tests/source-smoke.e2e.mjs`의 원본 ESM 시작과 실제 9종 혼합 전투입니다.
같은 흐름에 보스 광역의 대상별 충전, 카드 선택·다음 전투 덱 유지·재도전 초기화와 양 진영 5개 스킬의
공유 모델/표시 DTO 렌더를 확인합니다. 기존 `tests/smoke.e2e.mjs`의 상세 검증은 필요할 때 별도로 실행합니다.
개발 중 집중 모델·모션 검증은 임시로만 실행하고 결과를 PR에 남기며 영구 단위 테스트 파일은 추가하지 않습니다.

공식 GitHub CI의 Chromium은 SwiftShader를 사용합니다. source smoke는 원본 `index.html`과 ESM을 제공하고,
manifest에 고정된 CDN 모듈 요청을 같은 해시의 `vendor/upstream` 오프라인 파일로 가로챕니다.
라이브 CDN 가용성이나 실제 GPU/모바일 기기 검증과는 구분합니다. 모든 소스와 SVG는 번들 생성 없이
제품과 같은 파일을 읽으며, 스크린샷은 실제 RAF와 FarmSession 표시 DTO를 통과한 결과입니다.

## 양 진영의 공통 카드와 기술 HUD

탑 강화층의 유저 카드 선택 성공 뒤, 보스도 같은 `rollCardOffers`로 스탯·패시브·스킬 후보 3장을 만들고 동등 확률로 1장을 자동 선택한다. 정의, 종류 가중치 8:1:1, 희귀도, 중복 강화·상한을 공유한다. 명시적 제외는 복사 스킬과 불사 패시브뿐이다. 스킬은 최대 3종·각 5레벨, 스탯/패시브는 카드별 10장이다. 슬롯이 가득 차도 스탯·패시브는 계속 나오고 스킬만 보유 기술 강화로 제한한다. 전체 풀이 소진되면 카드 없음으로 안내하며 진행 입력을 막지 않는다. 이벤트 문은 보스 카드 획득을 발생시키지 않는다.

`applyTowerCard`가 획득을 한 번 확정하고, receipt에는 후보·선택 index·시작/종료 시각만 기록한다. UI는 기존 doorCard 영역을 1.8초 동안 보스 후보로 바꾸며 0.9초에 선택을 강조한다. 별도 타이머나 UI가 모델을 다시 적용하지 않는다. 이 동안 다음 문 입력은 모델에서도 잠긴다. 새 도전은 양쪽 카드를 초기화하며 높은 층 직접 시작도 기존 유저 흐름처럼 빈 덱이다. 농장에는 적용하지 않는다.

보스 본체와 일반 소환 부하는 같은 enemy 진영이다. 스탯은 같은 Unit의 statModifiers, 패시브는 같은 합산/조건 함수로 적용한다. enemy는 player 전역 카드가 적용되지 않은 원본 병종 스탯을 읽는다. 부하 사망은 복수·도우미·망치 조건에 기여하며 복제 분신과 사망 분열 자식의 반복 충전은 제외한다. 전투별 사망 누적은 다음 전투에 초기화한다. 피해/적중/치명/피격 이벤트는 진영 소유권을 분리하며 스킬 피해는 스킬 조건을 충전하지 않는다.

스킬 model/presentation은 하나이며 차이는 definition의 역할 profile 값이다. 아래 수치는 초기 구현 조정값이지 사용자 확정 밸런스나 실기기 난이도 검증값이 아니다.

| 항목                  | 보스 profile / 공통 규칙                                   |
| --------------------- | ---------------------------------------------------------- |
| 거대화                | 몸집 1.25배, 나머지 공격 3배·방어 +100·20초·대상 수는 공유 |
| 낙뢰                  | 적중 50회, 고정 착점 0.7초 예고 뒤 광역                    |

| 유성우                | 적중 100회, 공유 낙하/발사 간격                            |
| 우주선                | 유저와 같은 치명타 10회, 두꺼운 실제 판정 빔·최대 3명      |
| 뇌운                  | 적중 75회, 큰 구름 하나에서 최대 3명 머리 높이로 분기      |

고정 회복100은 기본 보스HP 1층200/10층1435/30층6200/50층10200 대비 50%/6.97%/1.61%/0.98%이므로 비율 회복과 일괄 축소하지 않았다. 몸체 radius/height와 공격 geometry는 별개다. 거대화 배율은 실모델 몸체와 실제 렌더에 같이 반영한다. 적중은 피해 대상별 1회이므로 광역에도 50/100/75 문턱을 유지한다.

### 공격 스킬의 크기 기준 (0.41.6)

공통 profile의 `sizeReference`가 병력은 대상(`target`), 보스는 시전자(`caster`)를 선택한다. 보스의 초기 `sizeScale=0.8`에 대해 `D = 시전자 현재 몸체 반경 × 2 × 0.8`을 기준 직경으로 사용한다. 이는 이번 구현의 초기 조정값이다. Unit의 현재 radius/height는 이미 거대화를 반영하므로 배율을 다시 곱하지 않는다. 피격 대상이 작아져도 보스 공격 크기는 줄어들지 않는다.

- 낙뢰의 예고·피해 원 반경은 D/2이며, 번개 시각 크기도 같은 기준에서 나온다. 착점 고정·0.7초 예고·회피 규칙은 유지한다.
- 우주선의 원반 기준 폭과 레이저 전체 판정 폭은 D이다. 피해 검색에는 전체 폭의 절반을 반경으로 사용한다. 본체가 빔 위에 그려지는 기존 레이어 순서는 유지한다.
- 운석과 유성우의 각 착탄 피해 원 반경은 D/2이며 그림은 이 실제 radius를 읽는다. 흩뿌림은 D/2에 실제 피격 대상 반경을 더한 기존 무작위 배치 계약을 쓴다.
- 뇌운의 안정된 구름 기준 폭은 D, 대상 검색 반경은 D/2이다. 검색 원 전체가 광역 피해를 입는 것은 아니며 최대 세 대상을 고른 뒤 기존 분기 번개로 개별 타격한다. 등장·소멸의 구름 퍼짐은 안정된 폭보다 클 수 있다.

위치·머리 연결 높이는 여전히 실제 피격 대상의 몸체를 읽는다. 시각 크기 참조와 대상 부착 좌표를 분리하며, 해석된 크기를 실제 효과와 FarmSession DTO로 전달한다. 병력의 기존 대상 크기 시각·고정 판정 반경은 바꾸지 않고 위력·조건·쿨·대상 수 역시 유지한다.

양 진영은 효과 발동 성공 시점부터 슬롯별 5초 쿨타임을 공유한다. 쿨 중 조건 충전은 허용하지만 조건·쿨 종료를 모두 만족해야 발동한다. 보스는 물리 패턴 뒤 준비0.8초→발동→회복0.45초 동안 자발 이동·평타와 새 시전을 멈춘다. 발동 전 기절·사망은 충전/쿨 소비 없이 취소하며, 기존 UFO/뇌운의 지속효과는 유지된다. 전투 종료에는 효과와 버프를 정리한다.

보스 HP 아래와 유저 HUD는 같은 RelicDock의 아이콘·충전바·쿨 부채꼴·ready 표현을 쓴다. 실제 runtime 조건량과 prepare/recover 상태를 읽고 터치 상세에서 효과·조건·남은 시간을 표시한다. 가짜 발동 타이머는 만들지 않는다. 카드 화면 역시 기존 테마/선택 컴포넌트를 재사용하고 독립 흰색 패널은 제거했다.

기존 디스크 저장 0.30~0.41은 유지하며 진행 중인 탑은 원래처럼 디스크 복원하지 않는다. 내부 snapshot에는 거대화 배율/대상 세대와 공통 Unit 상태를 보존한다. 버프·회복의 기존 편성 병력(대기 포함) 범위는 유지하고 공격 대상만 현재 전장의 combatUnits로 제한한다.

공식 source smoke는 모든 기능·UI 상태 assertion을 기본 실행한다. 이미 검토한 화면의 중복 저장은 기본 생략하고, 필요한 렌더 검토에만 같은 스크립트의 `BUDMORI_CAPTURE_SHARED_HUD=1` 옵션으로 PC HUD 이미지를 저장한다. 이미지 저장 여부가 실전 스킬·DTO·모바일 레이아웃 검증을 끄지는 않는다.

0.41.6의 크기 검증은 같은 혼합 전투 안에서 다섯 보스 기술의 중심·범위 안팎 실제 피해와 실제 표시 DTO를 확인한다. 낙뢰·우주선 대표 이미지만 기본 저장하며, 이미 검토한 동일 제품의 반복 실행은 `BUDMORI_CAPTURE_BOSS_SCALE=0`으로 이미지 저장만 생략할 수 있다. 기존 기능 assertions는 동일하게 실행한다.
